**Related issue:** follow-up to [docktor-app/docktor#33](https://github.com/docktor-app/docktor/issues/33) (Phase 13, 13-01 D-04/D-05 moving-tag dialog state). This quick task extends the dialog's Update Images shortcut to pinned (non-moving) tags; it does not change D-04/D-05's moving-tag behaviour.

<objective>
In the per-service Upgrade dialog, also offer the "Update Images" button for services pinned to a non-moving tag such as a semver (e.g. `memos:0.31`), because a pinned tag can be republished with a new digest without any version change — the update checker flags it, the Upgrade arrow appears, but today the dialog offers no way to pull that same-tag update. The moving-tag explanatory Alert must NOT be shown in the non-moving case. Moving-tag behaviour stays exactly as 13-01 shipped it.

Purpose: Close the dead end where a digest-only update on a pinned tag opens a dialog with nothing actionable ("already on the newest known version" / "not checked yet" and a disabled Upgrade).
Output: Updated `service-upgrade-dialog.tsx`, updated/extended unit tests, corrected docstring in `update-images-action.ts`.
</objective>
