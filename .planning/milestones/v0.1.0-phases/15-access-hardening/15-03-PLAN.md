**Implements:** [docktor-app/docktor#45](https://github.com/docktor-app/docktor/issues/45) (the TOTP second step at sign-in) and the user-facing half of [docktor-app/docktor#46](https://github.com/docktor-app/docktor/issues/46) (a clear message when sign-in is rate limited).

<objective>
Give the login page its second step: after a correct password, users with 2FA enter a code from their authenticator (or a recovery code), may trust the browser for 30 days, and see a precise "try again in N minutes" message when rate limited.

Purpose: 15-01 made the server answer {twoFactorRedirect: true} and enforce 5 attempts per 15 minutes; without this plan a user with 2FA cannot sign in through the UI at all. The copy and interaction rules come from the approved 15-UI-SPEC.md (Login step 2, Rate limiting, Interaction Contract).

Output: the better-auth twoFactorClient plugin, two pure helpers (rate-limit message, auth-error classification), the TwoFactorStep component, and the extended LoginForm, all unit tested.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user -> login form | passwords, TOTP and recovery codes are typed here |
| browser -> /api/auth/* | the server is authoritative for every verification and every rate limit; the client only presents results |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-19 | Information Disclosure | TOTP / recovery code inputs | medium | mitigate | autoComplete one-time-code (TOTP) / off (recovery), spellCheck false, no console output, codes never stored outside react-hook-form state; form reset on step change |
| T-15-20 | Spoofing | client-side retry loops amplifying brute force | low | mitigate | no automatic retry on any error; the server's 5-per-15-minutes limit (15-01) is the control; the UI only reports X-Retry-After |
| T-15-21 | Tampering | recovery code altered before verification (case folding) | low | mitigate | trim only, never change case (RESEARCH Pitfall 15); unit test asserts the exact value sent |
| T-15-22 | Elevation of Privilege | client decides who may skip 2FA | low | transfer | trust-device and second-step decisions are made by better-auth on the server; the checkbox only sends trustDevice |
| T-15-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this plan (better-auth's client plugin ships in the installed package); any unplanned install must stop for a blocking human legitimacy check |
</threat_model>
