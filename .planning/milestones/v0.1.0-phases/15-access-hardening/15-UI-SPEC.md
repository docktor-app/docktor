# Phase 15 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of UI in this phase** (everything else in Phase 15 is server-only):

1. Login second step (TOTP code, recovery-code alternative, trust-device checkbox) and 429 messaging on the login form (D-04, D-05, D-12).
2. New `/account` page with a single Security section: 2FA status, enroll, disable, regenerate recovery codes, instance-wide mandatory-2FA toggle (D-02, D-06, D-07, D-08).
3. Forced-enrollment redirect state when mandatory 2FA is on and the user has not enrolled (D-01).
4. Nav entry for the Account page (Claude's discretion, decided below).

Sources: CONTEXT.md D-01..D-10, D-12 (decisions pre-populated, not re-asked); RESEARCH.md Patterns 1, 3, 4, 5 (flow, endpoints, `X-Retry-After`, qrcode.react); CLAUDE.md Frontend UI rules; existing `login-form.tsx`, `app-sidebar.tsx`, `nav-user.tsx`, `ToneBadge`, `Section`, `Page`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), badge internals |
| sm | 8px | Gap between a control and its inline helper text; button-group gap (`gap-2`) |
| md | 16px | Default stack inside dialogs and forms (`space-y-4`); row padding (`py-4`); code grid gap (`gap-4` between columns is 16px, rows `gap-2`) |
| lg | 24px | Section-to-section spacing (`PageContent` `space-y-6`), dialog padding (shadcn default `p-6`) |
| xl | 32px | Space between QR block and manual-key block on mobile stack |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Layout constants for this phase: Account page content max width `max-w-2xl` (672px); login card keeps its existing `max-w-sm`; QR code renders at 176px square inside a 8px-padded white (`bg-white`) wrapper (quiet zone, required for scanning in dark mode); dialogs use shadcn default `sm:max-w-lg`.

Exceptions: QR size 176px (multiple of 4, fixed for scan reliability). shadcn primitives keep their internal values (e.g. `Input` h-9 = 36px). Touch targets: all buttons stay shadcn default (36px height); on `< sm` viewports dialog footers and the login step buttons are full width (`w-full`, stacked with `gap-2`) so the tap area is >= 44px wide and the layout holds in the Playwright `mobile-chromium` project.

## Interaction Contract

**Login flow (D-04, D-05).** `LoginForm` keeps step 1 unchanged. On `signIn.email` resolving with `data.twoFactorRedirect === true`, swap the Card content to `TwoFactorStep` (local `step` state; no route change, so the typed email/password are discarded and not retained). On success of `verifyTotp` / `verifyBackupCode` (with `trustDevice` from the checkbox), `navigate("/")`. If the user owes enrollment, `ProtectedRoute` then redirects to `/account`. "Back to sign in" returns to step 1 with an empty password. TOTP input: `inputMode="numeric"`, `autoComplete="one-time-code"`, `maxLength={6}`, digits-only sanitising, auto-focus on mount; Enter submits. Recovery input: trim whitespace, do NOT change case (verification is case-sensitive, RESEARCH.md Pitfall 15), `autoComplete="off"`, `spellCheck={false}`. Mode switch keeps the trust checkbox state and moves focus to the new input. Forms are react-hook-form + Zod (`totpCodeSchema`, `recoveryCodeSchema` in `@docktor/shared/validation/account.ts`).

**Account route and nav.** Route `/account` inside the protected `AppLayout` group. Nav entry decision (Claude's discretion): the sidebar "Platform" group is for product areas, so Account is added as the first item of the **`NavUser` dropdown** ("Account", `UserRound` icon, `Link` to `/account`) above "Sign out". Breadcrumb: `Account`. Sidebar footer user block stays the visible entry point. The forced-enrollment redirect target is `/account`.

**Page composition (D-08).** `routes/app/account.tsx` = orchestrator: calls `useAccountSecurity()`, renders `Page` / `PageHeader` / `PageContent`, then `<EnrollmentRequiredAlert/>` (only if `enrollmentRequired`) and one Security `Section` containing `TwoFactorSection` and `MandatoryTwoFactorRow` separated by `Separator`. No Card, no `UnsavedChangesGuard` (D-08). Each row: `flex flex-col gap-4 sm:flex-row sm:items-start sm:justify-between py-4`; title + pill on the left, actions on the right (wrap below on mobile).

**Dialog behavior.** Enroll and regenerate dialogs are single `Dialog`s with internal step state. While on a step that holds unsaved secrets (enroll steps 2-3, regenerate step 2): `onInteractOutside` and Escape are prevented; closing is only via the explicit "Cancel setup" button (nothing is active server-side until the first TOTP verifies, so no extra confirm is needed; the codes are inert and replaced by the next attempt). On step 1 of any dialog, outside click/Escape closes normally. Focus moves to the first field of each step; on close, focus returns to the trigger button (Radix default). Step changes announce via `aria-live="polite"` on the description.

**Enroll flow state rules (RESEARCH Pitfalls 6, anti-pattern "enable twice").** "Set up two-factor authentication" is rendered only when `twoFactorEnabled === false`. The status flips to Enabled only after `verifyTotp` succeeds in step 3; closing earlier leaves status "Not enabled". The server-provided `totpURI` and `backupCodes` live only in dialog component state (never persisted, never logged, cleared on close).

**QR rendering.** `QRCodeSVG` from `qrcode.react`, `size={176}`, `level="M"`, `marginSize` off, inside an 8px-padded `bg-white` square so dark mode keeps a scannable quiet zone. `role="img"`, `aria-label="QR code for your authenticator app"`. Never use a third-party QR service. Manual key is parsed from the `secret` query param of the `totpURI`, shown in `font-mono text-sm break-all` inside a `bg-muted rounded-md p-2` box.

**Mandatory toggle (D-02, D-03).** `Switch` with visible label and `aria-describedby` pointing at the body text. States: (a) caller lacks 2FA and setting is off: Switch disabled, helper text visible (not tooltip-only, for touch/keyboard users); (b) caller has 2FA, setting off: toggling on opens the AlertDialog; the Switch only flips after the server confirms (pessimistic, no optimistic rollback logic; Switch is `disabled` while the request is pending); (c) setting on: toggling off applies immediately. The Switch is a single control, not a form, so it is exempt from react-hook-form.

**Disable guard.** While the mandatory setting is on, "Disable two-factor" is `disabled` with `aria-disabled` and a Tooltip plus the same text rendered as `sr-only` description (RESEARCH.md diagram: disable-while-mandatory guard). Turning mandatory off first re-enables the button.

**Session revocation feedback (D-10).** Because other sessions are revoked on enable / disable / regenerate, success toasts say so (copy above). The current session stays signed in; no re-login prompt.

**Rate-limit UX (D-12).** 429 on any of: sign-in, verify-totp, verify-backup-code, and Account password forms renders the Rate limiting copy above. Never auto-retry. Never clear the code input on 429 (so the user can retry after the wait); clear it on "invalid code".

**Forced enrollment (D-01).** `ProtectedRoute` consults `useAccountSecurity()`; if `enrollmentRequired` and the path is not `/account`, `<Navigate to="/account" replace />`. The server (`requireAuth` 403 with code `TWO_FACTOR_ENROLLMENT_REQUIRED`) remains authoritative; any `apiFetch` receiving that code also routes to `/account`. On `/account` with `enrollmentRequired`: Alert + orange pill + auto-open enroll dialog (once per mount; closing it leaves the primary CTA visible). Sidebar stays visible; other items bounce back to `/account`; "Sign out" in `NavUser` always works.

**Motion.** No custom animation. Existing `motion-reduce` behavior in `ToneBadge`/`StatusDot` is unchanged. Dialog transitions are shadcn defaults.

**Accessibility.** All inputs have visible labels; errors are tied with `aria-describedby` (shadcn `FormMessage`) and banner errors use `role="alert"`; copy buttons and the icon-only manual-key copy button have `aria-label`s; the code grid is a `<ul>` of `<li>` with `font-mono` (screen readers read it as a list of 10 items); color is never the only status signal (pills carry text); contrast follows the shadcn neutral theme in both modes.
