**Implements:** [docktor-app/docktor#24](https://github.com/docktor-app/docktor/issues/24) — the remaining two client surfaces of the uptime view: the per-stack uptime column on the stack lists (D-16) and the configurable retention window in Settings (D-10), on top of 14-04's endpoints and 14-07's formatters.

No SPEC.md exists for this phase, so no probe-derived predicates were generated. The UI-SPEC `## UI Considerations` rows for the stack-list Uptime column and the retention card are lifted into must_haves.

<objective>
Let a user compare every stack's availability at a glance from the Dashboard or the Stacks page, and choose how many days of uptime, incident and health history Docktor keeps.

Purpose: D-16 puts uptime "where stacks already are": besides the Overview card (14-07), a column on the stack rows. D-10 makes the window configurable globally (1-365 days, default 30). Because shortening it schedules irreversible deletion of history (14-12's daily pruner), UI-SPEC G gates a decrease behind a confirmation dialog — the phase's only destructive action.

Output: one API function, one hook, one domain badge, the StackList column (fed by both list pages), two settings API functions, one settings card, default Playwright stubs and one e2e spec.
</objective>
