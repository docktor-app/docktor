<objective>
Put each stack's local backup repository into the disk picture, and make the daily scan safe against `du` failing, timing out or being absent.

Purpose: 14-02 measures `<stack>/volumes/*`, serves `GET /api/storage` with a backups list and a volumes + backups total, and stores `Stack.backupSizeBytes`, but nothing writes that column yet.
- D-14 (amended) puts local backups at `<stack>/backups` (the restic repository BackupService writes), shown as one row per stack and counted once in the grand total.
- RESEARCH Pitfall 8: `du` exits 1 when one entry is unreadable but still prints a total. It is missing on the Windows dev host and can hit its timeout on large trees.
- RESEARCH Pitfall 9: `backups` can be a symlink into the read-only host mount.

Re-slice note (2026-10-07 revision): this plan is 14-02's former Task 2, moved verbatim. Its only addition is the port widening in step 2: 14-02 now declares `DiskUsageScannerPort` with the two members it uses, so this plan adds `isRealDirectory`. 14-02's estimate sat at the 100k smart-zone budget before the RESEARCH Open Question 3 decision added a test case and a gate. 14-02 is the tracer slice of #27's server side; this plan is its expansion.

Output: one widened port, scanner failure handling and the lstat check, the per-stack measurement step in the job, and unit and integration tests. 14-05's Backups section renders the rows this plan produces.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem (`DOCKTOR_STACKS_DIR`, host `/` mounted read-only) → DiskUsageJob | `<stack>/backups` and the entries under each stack can be created or replaced by stack containers, so they are untrusted |
| DiskUsageJob → `du` child process | argv built from `getStackPath()` and fixed names; exit status and stdout come back from an external tool |
