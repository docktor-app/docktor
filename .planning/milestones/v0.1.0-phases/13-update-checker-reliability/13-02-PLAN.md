**Implements:** [docktor-app/docktor#34](https://github.com/docktor-app/docktor/issues/34) (D-07, D-08, D-09).

<objective>
Stop service status sitting at "unknown" for up to 60s after a deploy. StatePoller drops Docker events while a stack is DEPLOYING/UPDATING, and `replaceServices()` wipes `containerState`, so only the 60s reconcile catches up. This plan adds an application-layer catch-up that runs every time a deploy-family operation leaves its transitional status, on success and on failure. The catch-up:
- reads the stack's real containers through the Docker Engine API;
- writes per-service state;
- derives the stack status with the same shared rule StatePoller uses;
- emits StatePoller's per-service `stack.container_state_changed` event, which the client already consumes live (no client change, D-09).

Tracer (Task 1): extract the derivation to `domain/`, build the catch-up's happy path, and wire it into `deployStack`'s success exit. Task 2 covers the remaining exits (every failure branch, `updateImages`, `upgradeServiceImage`), the explicit non-callers, and the catch-up's edge cases (missing containers, inspect failures, transitional race, empty stack, idempotency, never-reject).

Output: `domain/stack-state-derivation.ts`, `application/container-state-catch-up.ts`, a 10th `StackService` dependency, and tests.
</objective>
