<objective>
Fix the Upgrade dialog for moving-tag services. Today, the per-service Upgrade arrow on a checked moving-tag service (for example `nginx:latest`) opens a dialog that wrongly says the registry has not been checked yet, because `latestTag` and `candidates` are null/empty for moving tags by design. After this plan:
- The server tells the client whether the current tag is moving (`isMovingTag`, D-06).
- The dialog shows a distinct moving-tag state with a disabled Upgrade button (D-04).
- That state offers an Update Images shortcut, which runs the same stack-level action as the header menu (D-05).
- The Upgrade arrow stays where it is (D-03).
- #31 and #32, already shipped in Phase 11, are verified and pinned with tests so they can be closed.

Tracer (Task 1) wires `isMovingTag` from the domain through `StackService` and the tags route into the dialog's moving-tag state. Task 2 adds the Update Images shortcut (with a shared helper), the D-03 regression test, and the #31/#32 verification.

Output: shared moving-tag definition, `isMovingTag` on the tags response, the moving-tag dialog state, the shared `runUpdateImages` helper, and regression tests.
</objective>
