## Planning notes

- This plan leads with the [BLOCKING] schema-push task required by the phase's schema-push gate (migration before any DB-touching verification); the tracer is Task 2. All Prisma schema changes of the phase live in this one migration (including `deployWarnings` for 12-08 and `templateUpdateAvailable` for 12-11) so there is exactly one [BLOCKING] migration and later plans in other waves never edit `stack.prisma`.
- The template cache (`DOCKTOR_TEMPLATE_CACHE_DIR`, default `<os tmpdir>/docktor-template-cache`) is disposable: the parsed index lives in the database, and a lost cache is simply re-cloned on the next sync.
- First-run UX (UI-SPEC "Templates are loading for the first time"): `GET /api/templates` awaits the first sync of never-attempted repos, so the client shows its skeleton while that single request is pending — no polling.

<assumption_delta_decision>

</assumption_delta_decision>
