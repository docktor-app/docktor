**Implements:** [docktor-app/docktor#7](https://github.com/docktor-app/docktor/issues/7) (check environment variables before startup; blocking errors vs non-blocking warnings), server side. The UI banner is plan 16-03.

<objective>
Make Docktor refuse to boot on a broken required environment, with one readable report of everything that is wrong, and compute the non-blocking warnings once at boot so the UI can show them.

Purpose: today a missing BETTER_AUTH_SECRET crashes inside better-auth with an obscure error, and a missing or malformed ENCRYPTION_KEY only fails much later, the first time a backup, SMTP password or 2FA secret is encrypted (CONTEXT D-10). RESEARCH Pitfall 1 found that a check written in the body of server/src/index.ts would still run too late, because index.ts statically imports app.js and therefore lib/auth.ts, which reads the auth variables at module evaluation. This plan builds the check as one Zod schema plus pure evaluators (D-13), runs it as the first statement of the entrypoint, loads app.js afterwards with a dynamic import, and stores the warnings for GET /api/settings/environment.

Output: shared report DTO, a pure check module, an injectable bootstrap, a module store, an application service, one authenticated route, the rewired entrypoint, unit + architecture + integration tests.
</objective>
