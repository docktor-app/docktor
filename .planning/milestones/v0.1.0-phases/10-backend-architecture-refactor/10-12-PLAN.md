<objective>
Move the notification side effect onto the bus (D-15 item 1): the six places that call the notification service directly emit a domain event instead, and a subscriber turns those events into notifications.

There is a real, deliberate behavioural consequence here that must be recorded rather than discovered later. Today five of those six call sites `await` the notification, which means they await an SMTP send inside a backup or restore flow. After this plan they emit synchronously and the subscriber notifies independently. That is precisely what D-17's isolation is for — a mail server being down must not affect a backup — but it changes when a notification is attempted relative to the operation, and one call site (the backup abort path) has documented history around exceptions escaping it.

Purpose: D-15 item 1's framing is only half true today — stack error and unhealthy notifications already go through an indirection (a job subscribing to the broadcaster), while backup, restore and disk notifications are direct calls. This plan makes both halves uniform.
Output: notification-intent domain events, a notification subscriber, six migrated publishers, and a watcher repointed from the broadcaster to the bus.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application -> SMTP server | Notification content leaves the process; a failure here must not affect the operation that triggered it |
| bus -> notification subscriber | A new indirection between an operation's failure and the operator learning about it |
| server -> browser | The notification-created live event drives the notification log's real-time updates |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-39 | Repudiation | notification delivery after the indirection | high | mitigate | Per-event composition tests assert type value, subject and message are byte-identical to today; the watcher's de-duplication, timer and recovery assertions must pass unedited. A silently non-matching subscription produces silence rather than an error, which is why every alert path keeps a test rather than relying on the migration being obviously correct |
| T-10-06 | Denial of Service | mail outage stalling a backup | high | mitigate | This is the threat the plan closes: the emitting operation no longer awaits the mail send, and a test asserts a backup completes normally when the notification path rejects. The change is recorded explicitly in the summary rather than left implicit |
| T-10-40 | Tampering | persisted notification type values | high | mitigate | The restore events' reuse of the backup-failure type value is carried across verbatim, so rows written before and after the phase render identically; the before/after template table in the summary is the evidence |
| T-10-09 | Information Disclosure | notification payloads on the bus | medium | mitigate | The bus logs only the event key and the error (plan 10-03), never the payload — which after this plan carries user-facing message text and stack display names |
| T-10-41 | Information Disclosure | recipient addresses | medium | accept | Unchanged: recipients are resolved inside the notification service from the user repository (plan 10-01) and never travel on the bus; the intent events carry no address |
| T-10-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed |
