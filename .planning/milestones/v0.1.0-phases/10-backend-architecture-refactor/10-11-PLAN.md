<objective>
Move every state and configuration broadcast onto the domain-event bus, and turn the live-state broadcaster into an ordinary subscriber (D-15 item 3).

The binding constraint is D-18: the server-sent-events stream that Phase 08 validated must emit exactly the same events, carrying exactly the same fields, in exactly the same order, at exactly the same points relative to their database writes. This is an internal wiring change with a zero-delta external contract.

Purpose: after this plan a new consumer of "a stack changed state" — Phase 14's health and uptime work, for example — subscribes to the bus instead of being threaded through `StackService` and `BackupService` again.
Output: a bridge subscriber, two application choke points emitting instead of publishing, and four job publishers doing the same.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server -> browser (server-sent events) | Every connected client's live view is driven by this stream; its contents and ordering are an external contract |
| publisher -> bus -> subscribers | A new fan-out point between a database write and the live-state broadcast |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-06 | Denial of Service | status-transition wrappers | high | mitigate | The publisher-side try/catch is kept at all three wrappers (recorded before and after), complementing the bus's own per-subscriber isolation. 10-RESEARCH.md Pitfall 2 establishes these are complementary, not redundant; removing either reopens the stranded-transitional-status failure mode from plan 05.1-02 |
| T-10-36 | Tampering | event-shape drift through the bridge | high | mitigate | The bridge maps every field explicitly with no spread and no cast, asserted by a grep; the subscriber test asserts deep equality per event against expected objects written literally from the current call sites, not derived from the implementation |
| T-10-37 | Repudiation | ordering and timing drift | high | mitigate | The bridge is synchronous (asserted by a grep for async constructs) and the emit still happens strictly after the write resolves at every migrated site (asserted per wrapper). A queued or deferred bridge would reorder what a client observes |
| T-10-38 | Spoofing | configuration-change origin discriminator | medium | mitigate | The app-origin literal in the stack service and the external-origin literal at each file-watcher site stay hardcoded per call site rather than becoming a parameter or a default, so a future publisher cannot ship an untagged or mistagged event — the exact reasoning recorded for this field in Phase 08 |
| T-10-09 | Information Disclosure | bus error logging | medium | mitigate | Unchanged from plan 10-03: the bus logs the event key and the error, never the payload |
| T-10-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed |
</threat_model>
