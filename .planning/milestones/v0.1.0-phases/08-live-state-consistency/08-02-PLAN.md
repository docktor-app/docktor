<objective>
Close the server-side half of two of phase 08's three diagnosed UAT gaps.

**G-08-2 (major, test V2):** the `config_changed` SSE event carries no origin, so `client/src/hooks/use-stack.ts` shows the "Configuration file changed externally" toast for every `config_changed` event unconditionally — including the one `StackService` itself publishes right after an app-initiated compose or env save. Compounding bug: `updateStack()`'s env-save branch never calls `repo.updateEnvHash()`, so `Stack.lastEnvHash` stays stale after an in-app env save; when chokidar's own "change" event for that same write later fires, `FileWatcher.handleEnvChange()` compares against the stale hash, sees a mismatch, and fires a second, genuinely-misclassified `config_changed` broadcast.

**G-08-6 (blocker, test V6):** `StackService.updateStack()` calls `createComposeConfig(input.composeContent)` with no try/catch. The underlying `parseComposeContent()` throws a raw `new Error(...)` on invalid YAML — not an `AppError` subclass — so Fastify's global error handler falls through to its generic catch-all and returns an opaque 500 instead of a typed 400 carrying the parser's own message. Compounding gap: a successful save never calls `repo.clearConfigError(id)`, so a valid re-save of previously-broken content leaves the red config-error indicator stuck.

Purpose: a user saving valid config through the app must never see a toast claiming their own change came from outside the app, and saving broken YAML through the compose editor must behave like every other validation failure in this codebase — a typed 400 with the parser's message, not a server crash.

Output: `config_changed` broadcasts carry a `source: "app" | "external"` discriminator, set correctly by both publishers (`StackService` and `FileWatcher`); `updateStack()`'s env branch keeps `lastEnvHash` in sync with what it just wrote; `updateStack()`'s compose branch translates a parse failure into `BadRequestError` and clears `configError` on a successful parse. The client-side half of G-08-2 — actually gating the toast on `source` — is a separate, independent fix closed by the companion plan `08-03-PLAN.md`; this plan does not touch any client file.
</objective>
