## Decisions (non-interactive defaults)

| ID | Decision | Grounding |
|----|----------|-----------|
| D-01 | Two labelled sidebar sections: **Platform** (Dashboard, Stacks, Templates) and **System** (Storage, Settings), in that order. "Platform" is the existing label, kept for continuity. | Issue #93 asks for "clear section labels, with a defined order" and says the final structure is agreed in the PR; today's single group is already named Platform. Storage and Settings are operator concerns, not day-to-day deploy work. |
| D-02 | The sidebar switches to `collapsible="icon"`. | `app-sidebar.tsx` currently renders `<Sidebar>` with the default `offcanvas` mode, which hides the sidebar entirely when collapsed; the roadmap success criterion "usable when the sidebar is collapsed to icons" cannot be met without it. This is a prop on `<Sidebar>`, so `components/ui/sidebar.tsx` stays untouched. |
| D-03 | Active-route matching becomes segment-aware: `pathname === to` or `pathname.startsWith(to + "/")`; `/` matches only exactly. Pure helper `isNavItemActive(pathname, to)` plus the nav model live in `client/src/lib/sidebar-nav.ts` and are unit-tested. | Success criterion 1 (parent keeps highlight on nested routes such as `/stacks/:id/backups/:backupId`) and avoids the false positive of `"/stacks".startsWith` matching a sibling like `/stacks-foo`. |
| D-04 | The Templates catalog is served at a new route `/templates`. The existing route `/stacks/create/templates` stays and mounts the same `TemplateBrowsePage` component (no redirect). The page derives its breadcrumb and title from the matched path. | Issue #94: "The existing path from Create Stack still works and reuses the same components." The "Start from Template" button on Create Stack keeps its current target so `create-stack-page.test.tsx` and `templates.spec.ts` remain valid. |
| D-05 | "Use Template" behaviour is unchanged on both routes: single-variant navigates to `/stacks/create?variant=<id>`; multi-variant opens `TemplateVariantDialog`. | Issue #94 acceptance: "same result as today". Existing `handleUse` is reused, not reimplemented. |
| D-06 | The running version is injected at build time through a Vite `define` constant `__APP_VERSION__`, read from `client/package.json` `version`, and declared for vitest in `vitest.config.ts` too. Exposed through `client/src/lib/app-version.ts` as `APP_VERSION` (string, no leading `v`). The UI renders it as `v{APP_VERSION}`. | Issue #88 notes two options (build-time injection or API); build-time needs no new endpoint and no request. Phase 21 (REL-01) bumps `client/package.json` to 0.1.1, so the block follows the release with no further change. `client/package.json` is already copied into the Docker client-build stage. |
| D-07 | Project links come from one module, `client/src/lib/project-links.ts`: `GITHUB_URL = "https://github.com/docktor-app/docktor"` and `DOCS_HOME_URL = "https://github.com/docktor-app/docks"`. Both open in a new tab (`target="_blank" rel="noopener noreferrer"`). | `docs-links.ts` documents that docs currently live as markdown in `docktor-app/docks` on GitHub; README links the same docs home. When a docs site exists, only this constant (and `DOCS_LINK_STYLE`) changes. |
| D-08 | Collapsed version block is a single icon menu button (`Info` icon) that opens a `DropdownMenu` containing the version label and the two links; expanded it is an inline row. | Version text ("v0.1.0") and two link icons cannot fit the 3rem rail (32px inner width). One focusable control with a tooltip and a menu is keyboard-reachable and matches the `NavUser` dropdown pattern directly below it. |
| D-09 | On mobile the sidebar sheet closes when a navigation link is followed (`useSidebar().setOpenMobile(false)` on nav item click). External links do not close it. | Without this, following a nav link on a phone leaves the sheet covering the new page. The mobile sheet is always rendered expanded, so the expanded block layout is what mobile shows. |
| D-10 | Typography and spacing add no new tokens. New code in this phase uses sizes 12/14/18/24 and weights 400/600 only. | Phase 20 owns the monospace font token (UI-03); this phase must not pre-empt it. The version text uses the existing sans font with `tabular-nums`. |
| D-11 | Touch targets: version-block link buttons and the collapsed trigger are 32px at `md` and up and 44px below `md` (`max-md:size-11`). Nav menu buttons keep shadcn's own sizing. | Phase 20 A11Y-01 lists specific controls and excludes the sidebar, but the new controls introduced here should not add new sub-44px mobile targets. |

## Spacing Scale

Declared values (multiples of 4), taken from the existing Tailwind scale used across the sidebar and Page primitives:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between the two link buttons; icon-to-label gap in dropdown items |
| sm | 8px | Sidebar group/menu gaps (shadcn `gap-2`), version row horizontal padding (`px-2`) |
| md | 16px | Nothing new; Templates grid gap (`gap-4`) is existing |
| lg | 24px | Page content padding (`p-6`, existing) |
| xl | 32px | Collapsed rail icon button size (`size-8`), desktop link button size |
| 2xl | 48px | Icon-rail width (`--sidebar-width-icon: 3rem`, shadcn) |
| 3xl | 64px | Not used |

Exceptions:
- Touch target 44px (`max-md:size-11`) for the version-block link buttons and the collapsed trigger below `md` (D-11). 44 is not on the 4-point scale but is the WCAG/Apple minimum and matches Phase 20 A11Y-01.
- Sidebar widths 16rem desktop / 18rem mobile / 3rem icon come from `components/ui/sidebar.tsx` and are not overridden.

## Layout and Interaction Contract

### 1. Sidebar structure (UI-06)

```
SidebarHeader      BrandLogo (logo expanded | mark collapsed)
SidebarContent
  SidebarGroup     label "Platform"
    Dashboard      LayoutDashboard   /
    Stacks         Layers            /stacks
    Templates      LayoutTemplate    /templates
  SidebarGroup     label "System"
    Storage        HardDrive         /storage
    Settings       Settings          /settings
Separator
SidebarFooter
  SidebarVersionBlock     (new)
  NavUser                 (existing, unchanged behaviour)
```

- Order and labels are fixed by `NAV_SECTIONS` in `lib/sidebar-nav.ts`; the component renders by mapping that model. Sections render in array order; each is a `SidebarGroup` with `SidebarGroupLabel`.
- Each `SidebarMenuButton` is `asChild` around a react-router `Link`, with `isActive={isNavItemActive(pathname, item.to)}` and `tooltip={item.label}` (new; required for the icon rail).
- Active states that must hold (unit-tested on the pure helper):

| Pathname | Highlighted entry |
|----------|-------------------|
| `/` | Dashboard only |
| `/stacks`, `/stacks/abc`, `/stacks/abc/backups`, `/stacks/abc/backups/xyz`, `/stacks/create`, `/stacks/import`, `/stacks/create/templates` | Stacks |
| `/templates` | Templates only (not Stacks) |
| `/storage` | Storage |
| `/settings/general`, `/settings/stacks` | Settings |
| `/account` | none (Account is reached from the user menu) |

- The active link carries `aria-current="page"` (set on the `Link` when active) so the highlight is not color-only.
- Section labels are non-interactive text (`SidebarGroupLabel` div). Collapsed: labels fade out via the shadcn classes; there are no separators between groups in the icon rail (the 8px group gap is enough).

### 2. Collapsed (icon rail) behaviour

- `SidebarTrigger` (in `PageHeader`) and the keyboard shortcut Ctrl/Cmd+B toggle expanded and icon states on desktop; the state cookie `sidebar_state` is shadcn's and unchanged.
- Header: expanded shows `BrandLogo` `variant="logo"` (`h-7 w-auto`); collapsed shows `variant="mark"` at `size-8`. Implement with `group-data-[collapsible=icon]:hidden` / `hidden group-data-[collapsible=icon]:block` wrappers in `app-sidebar.tsx`.
- Nav buttons show icon only; `tooltip` shows the label on the right on hover and keyboard focus.
- Version block collapsed: one `SidebarMenuButton` (icon `Info`, `size-8`, `tooltip="Docktor v{version}"`) as `DropdownMenuTrigger`. Menu content, `side="right"`, `align="end"`, `sideOffset={4}`, `min-w-56 rounded-lg`:
  1. `DropdownMenuLabel`: `Docktor v{version}`
  2. `DropdownMenuSeparator`
  3. `DropdownMenuItem asChild` → `<a>` "GitHub" with `Github` icon, opens `GITHUB_URL` in a new tab
  4. `DropdownMenuItem asChild` → `<a>` "Documentation" with `BookOpen` icon, opens `DOCS_HOME_URL` in a new tab
- Expanded and collapsed variants are both rendered in the DOM with `group-data-[collapsible=icon]` visibility utilities toggling which shows (so the cookie-restored collapsed state has no layout flash). The hidden variant must not be reachable by keyboard (`hidden` / `display: none`, not just `opacity-0`).

### 3. Version block, expanded (UI-01)

- Placement: inside `SidebarFooter`, above `NavUser`, below the existing `Separator`. A `px-2` row, `flex items-center justify-between gap-1`, height 32px (44px below `md`).
- Left: version text `v{APP_VERSION}` (12px/400, `tabular-nums`, `text-sidebar-foreground/70`), truncating. It has an accessible name via the surrounding row `aria-label` or visible text; the row is not interactive.
- Right: two `Button variant="ghost" size="icon"` link buttons (`asChild` around `<a>`), 32px (`max-md:size-11`), 4px apart:
  - GitHub: `Github` icon, `aria-label="Docktor on GitHub (opens in a new tab)"`, `title="GitHub"`
  - Docs: `BookOpen` icon, `aria-label="Docktor documentation (opens in a new tab)"`, `title="Documentation"`
- Icons `size-4` and `aria-hidden`. No hover tooltip is required in the expanded state (`title` plus visible context suffices).
- Both links: `href` from `project-links.ts`, `target="_blank"`, `rel="noopener noreferrer"`.

### 4. Mobile sidebar sheet

- The sheet renders the expanded layout (the `isMobile` branch of `Sidebar` ignores `collapsible`); the version block and nav therefore use the expanded variants with 44px link buttons.
- Following an internal nav link closes the sheet (D-09). Following an external link opens a new tab and leaves the sheet as is.
- The `NavUser` dropdown keeps its existing `side={isMobile ? "bottom" : "right"}`.
- No horizontal overflow at 360px width: version text truncates, never wraps the link buttons.

### 5. Templates page (UI-07)

Route table:

| Path | Component | Breadcrumb | Page title | Page description |
|------|-----------|------------|-----------|------------------|
| `/templates` | `TemplateBrowsePage` | `Templates` (single `BreadcrumbPage`) | `Templates` | `Browse the catalog and start a stack from a ready-made template.` |
| `/stacks/create/templates` | `TemplateBrowsePage` (same) | `Stacks / Create / Templates` (existing) | `Start from a Template` (existing) | none |

- Title, breadcrumb and description are chosen by comparing `useLocation().pathname`; everything below the header (loading, error, repo alerts, search, category filter, grid, variant dialog) is identical for both routes and remains the existing `TemplateGrid`, `TemplateCard`, `TemplateRepoAlerts`, `TemplateVariantDialog` components.
- Grid: `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`, `gap-4` (existing). Cards render through `Card`; category through `ToneBadge tone="neutral"`.
- Page file stays an orchestrator under ~80 lines: extract the header/breadcrumb selection into `routes/app/stacks/components/templates-page-header.tsx` if the page grows past the budget. The current file is 97 lines, already over budget, so the plan extracts the header and adds the zero-templates state as the only new section.
- Search input and category `select` keep their current labels (`Search templates`, `Category`). Native `select` is intentional (documented in `template-grid.tsx`: Radix Select renders two comboboxes in jsdom); do not swap it in this phase.
- From the sidebar Templates entry, "Use Template" then lands on `/stacks/create?variant=<id>`, where the Stacks entry is highlighted (the user is in the create flow). This is expected and not a bug.

## Accessibility and Testing Contract

- Every icon-only control has an accessible name (`aria-label`), icons are `aria-hidden`. External links announce "opens in a new tab".
- Keyboard: tab order is nav items (Platform, System), then version block (expanded: GitHub, Docs; collapsed: one menu button), then the account menu. In the collapsed rail the same order holds and tooltips appear on focus.
- Focus ring: `ring-sidebar-ring` (shadcn default) is retained; do not suppress outlines.
- Contrast: all text uses theme foreground tokens; `text-sidebar-foreground/70` for secondary text matches the existing `SidebarGroupLabel` treatment, so it is no weaker than current UI.
- Reduced motion: no new animation is introduced.
- Tests the plan must include (client, vitest + testing-library, queries by role/label):
  - `sidebar-nav` unit test: every row of the active-state table above.
  - `AppSidebar` render test: section labels `Platform` and `System` in order, five entries in order, `aria-current="page"` only on the active entry (MemoryRouter at `/stacks/abc/backups/xyz` highlights Stacks; at `/templates` highlights Templates only).
  - `SidebarVersionBlock` test: renders `v{version}` and two links with the expected `href`, `target="_blank"`, `rel` containing `noopener`; the collapsed menu lists the label and both links (render inside `SidebarProvider`).
  - `TemplateBrowsePage` test at both routes: correct title and breadcrumb per path; `Use Template` navigates to `/stacks/create?variant=<id>`; zero-templates empty state.
  - Router test: `/templates` and `/stacks/create/templates` both resolve to the page.
  - Version define: a unit test asserts `APP_VERSION` equals the `client/package.json` version (guards against hard-coding).
  - Playwright (run in CI only, per project memory): sidebar Templates entry → catalog → Use Template → create form prefilled; sidebar shows `v` + version; collapsed rail and mobile viewport (the project's `mobile-chromium` project) expose both links.
- Existing tests to keep green: `create-stack-page.test.tsx` (link to `/stacks/create/templates`), `templates.spec.ts`, `nav-user.test.tsx`, `app-layout.test.tsx` (mocks `AppSidebar`).
