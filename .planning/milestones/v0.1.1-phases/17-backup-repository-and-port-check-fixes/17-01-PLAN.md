**GitHub issue:** [#68 Configured SFTP/S3 backup repository is silently ignored](https://github.com/docktor-app/docktor/issues/68) (BKP-01, BKP-02, BKP-03)

<objective>
Make backup, restore and snapshot listing honour the configured restic repository. Today `BackupService` computes the repository inline and always picks `<stack.hostPath>/backups`, so a configured SFTP or S3 repository is ignored and every "off-site" backup lands on the same disk as the stack. This plan moves repository resolution into one pure domain function, applies the per-stack sub-repo layout (D-01), keeps `local` byte-for-byte unchanged (D-02), and hard-fails an incomplete remote configuration instead of silently falling back to the local path (D-05).

Purpose: an operator who configured SFTP or S3 gets off-host backups, and finds out loudly when the configuration is incomplete.
Output: `server/src/domain/restic-repository.ts` (new), its unit tests, and `BackupService` routed through it at all three call sites. SFTP key-file authentication (D-03, D-04) is plan 17-03; this plan already produces the correct SFTP repository location and validation.

Scope notes:
- No UI changes. The Settings card only offers `local` in v0.1.0; SFTP/S3 are configured through the settings API and onboarding wizard. Exposing them in the UI is issue #81 (out of scope).
- Switching an existing install from `local` to `s3`/`sftp` means snapshot listing shows the remote repository; the old local snapshots stay on disk under `<hostPath>/backups` and come back if the type is switched back. This is the intended BKP-01 behaviour.
- Restic exits with "unable to open config file" or code 10 for a not-yet-initialised remote repository, so the existing `isRepositoryNotFoundError` auto-init path initialises remote repos exactly like local ones.
</objective>
