**GitHub issue:** [#68 Configured SFTP/S3 backup repository is silently ignored](https://github.com/docktor-app/docktor/issues/68) (BKP-01 SFTP credential delivery, BKP-03 SFTP branch coverage)

<objective>
Complete SFTP support: after plan 17-01, SFTP runs target the right per-stack repository but nothing hands ssh the configured key, and the image has no ssh client at all. This plan makes the restic executor target-aware: it receives the resolved `ResticRepositoryTarget` instead of a bare env, and for `sftp` targets it writes the decrypted key to a 0600 temp file for exactly one restic process, passes it through `-o sftp.command` with `IdentityFile`, pins the host key on first use against a Docktor-managed `known_hosts`, and deletes the key in a `finally` block (D-03, D-04). It also removes the executor's now-dead URL builders (the domain resolver is the single source since 17-01) and adds `openssh-client` to the runtime image.

Purpose: an operator with an SFTP repository gets authenticated, host-pinned off-site backups instead of an ssh failure.
Output: target-aware `ResticExecutorPort`/`ResticExecutor`, `BackupService` passing targets, executor tests for identity lifecycle and pinning, Dockerfile change.

Location choice (Claude's discretion per CONTEXT): Docktor has no separate data directory; the only persistent volume is the stacks directory, so SSH state lives in `<stacksDir>/.docktor/ssh/` (override through the executor's `sshDir` option). A persistent location is what makes pin-on-first-use meaningful: the pin survives container recreation on upgrade. `.docktor` can never collide with a stack directory (stack ids are slugified: no dots), and the file watcher only reacts to `docker-compose.yml`/`.env`.
</objective>

restic facts this plan relies on (verified against restic source, internal/backend/sftp/sftp.go and internal/backend/shell_split.go; image pins restic 0.19.1):
- With `-o sftp.command=...` set, restic runs that command verbatim (split into argv by its own splitter) and does not add host, user or port; the command must therefore include the user, the host and `-s sftp`.
- The splitter separates on whitespace and on unquoted backslashes; a token fully wrapped in double quotes keeps spaces and backslashes. A quote in the middle of a word ends the token, so quote whole tokens (`-i "<path>"`, `-o "UserKnownHostsFile=<path>"`).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| BackupService -> ResticExecutor | Decrypted SFTP private key crosses from application memory into infrastructure |
| ResticExecutor -> filesystem | Key material is written to disk under the stacks volume for the lifetime of one restic process |
| restic/ssh -> remote SFTP server | Network connection to an admin-configured host; host identity must be verified |
| ResticExecutor -> logs | Every run logs the restic argv |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
