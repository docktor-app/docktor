**GitHub issues:** [#72 Migration dialog: real diff, explicit backup, stop old stack](https://github.com/docktor-app/docktor/issues/72) (MIG-04: the new stack must not be confused with the old one left running). Gap closure round 3 for **18-UAT.md G-18-22-status**, first half: "Match containers to a stack by project AND working_dir/config_files, via the same canonical path identity" (test 8: the new stack showed running because the old stack kept running under the same compose project name). The second half, the refusal of colliding project names, is plan 18-26.

<objective>
Attribute a container to a stack only when both its compose project and its compose directory match the stack, everywhere container state is read: StatePoller events, the reconcile, and the post-deploy catch-up.

Purpose: all three map containers to stacks by `com.docker.compose.project` alone (`findByComposeProject` looks the stack up by id = project). When an old copy of a stack runs from another directory under the same project name, its containers are counted for the new stack. Docker labels every compose container with `com.docker.compose.project.working_dir` and `config_files`, so the stack's own containers can be told apart by directory, compared through the canonical identity from plan 18-22 (labels are host paths; Docktor sees `/host`, same-path mounts and symlinks).
Output: a pure label helper, one application matcher used by the StatePoller and the catch-up, and tests including the migrated-stack scenario.

Out of scope: refusing the colliding migration itself (18-26), event ordering (18-23, a dependency), and stacks whose compose file sets `name:` or `COMPOSE_PROJECT_NAME` to something other than the stack id (pre-existing: such containers are never found by id; not part of this gap).
</objective>
