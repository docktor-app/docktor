**GitHub issues:** [#72 Migration dialog: real diff, explicit backup, stop old stack](https://github.com/docktor-app/docktor/issues/72), [#13 Hide Docktor's own stack from Import existing stack](https://github.com/docktor-app/docktor/issues/13) (the self-inspect adapter is shared). Gap closure round 2 for **18-VERIFICATION.md gap 1** ("A migration never reports success after silently failing to carry over the data of a bind mount the user selected") = **18-REVIEW.md CR-03**, with **WR-01** (request paths validated only after the old stack is stopped; unconfined copy source; no server-side collision backstop) folded in.

<objective>
Resolve every selected bind-mount source to a path Docktor can actually read, refuse what it cannot read before anything happens, and validate all request-controlled paths in preflight.

Purpose: in the documented deployment Docktor runs in a container with the host root at `/host`. A stack scanned at `/host/opt/app/docker-compose.yml` with `- /opt/app/data:/var/lib/data` yields a host path the container cannot see; today the copy treats ENOENT as "empty", creates an empty directory, the old stack is already stopped, and the migration reports success. This plan translates host paths through Docktor's own bind mounts (reusing `containerVisiblePaths`, no hard-coded `/host`), fails closed for anything not visible, keeps "create an empty directory" only for a visible but genuinely absent source and reports those in the preview, and moves every path check from execute into preflight (WR-01) so a bad request is a plain 400 with no stop, rename or rollback.
Output: a pure domain resolver with tests, an `OwnMountsPort` implemented by `DockerSelfStack`, destination rules in `migration-target.ts`, and `MigrationService` preflight/preview/execute using them.

Out of scope: WR-02 (unauthenticated setup routes) is a deferred human security decision (18-VERIFICATION.md human_verification); WR-10 (`/host` alias in managed/in-place detection) and WR-11 (rewriting `~` paths) stay open; this plan only refuses a converted `~` source instead of silently creating an empty directory. The client note for `emptySources` is plan 18-21.
</objective>
