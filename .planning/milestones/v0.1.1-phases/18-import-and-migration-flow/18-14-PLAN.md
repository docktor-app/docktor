**GitHub issues:** [#72 Migration dialog: real diff, explicit backup, stop old stack](https://github.com/docktor-app/docktor/issues/72). Gap closure for UAT gap **G-18-job** (server core): "Is the migration running in a job? It could take a lot of time." Progress streaming over SSE is plan 18-16, the client plan 18-17. Also carries the per-slug in-flight guard that 18-06 originally owned (moved here, see the 18-06 revision note).

<objective>
Run migrations as one-off background operations with an id, a status that survives a browser reload, and a 409 for a second start of the same migration.

Root cause (18-UAT G-18-job): `MigrationService.migrate` runs inside the POST handler (stop up to 120 s, unbounded copies, compose up with pulls), so proxy and browser timeouts make the client report failure while the server keeps going, and there is no in-flight guard. Locked decision: the endpoint returns an operation id (202), progress is streamed over the existing SSE/StateBroadcaster channel, a per-slug in-flight guard answers 409, status is queryable after reload, and both route families share it.

Design (Claude's discretion, recorded): an in-memory operation registry in the application layer, kept for the process lifetime with finished operations pruned after one hour (at most 50); a server restart ends any running migration anyway, so persistence would only keep stale "running" rows. Refusals stay synchronous because 18-06 split `migrate` into a side-effect-free `preflight` and `execute(plan)`.

Purpose: a slow migration never looks failed in the UI while it is still running, and cannot be started twice.
Output: shared operation contract, pure operation transitions, the operation service, 202 and status routes in both families, tests.
</objective>

| Boundary | Description |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-18-38 | Tampering (data loss) | concurrent starts of one migration | high | mitigate | Synchronous in-flight keys by slug and compose path, ConflictError before preflight, released in finally (Task 2 tests); 18-06's exclusive mkdir and record id remain backstops |
| T-18-39 | Information disclosure | GET operation list and by id | medium | mitigate | Import family behind requireAuth; setup family behind the wizard-complete 410 gate and `requireAdminAccount` (Task 3); ids are random UUIDs |
| T-18-40 | Denial of service | unbounded operation registry | low | mitigate | Finished operations pruned after one hour, at most 50 kept; running ones are bounded by the in-flight guard (Task 2) |
