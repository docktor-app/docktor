<objective>
Drive the migration UI from background operations instead of one long request.

Wire contracts this plan consumes (do not change them here):
- POST `/api/stacks/import/migrate` and `/api/setup/migrate` answer 202 with a `MigrationOperation` (shared `migrationOperationSchema`: id, stackId, displayName, composePath, backup, stopOldStack, status running|succeeded|failed, step, stepDetail, startedAt, finishedAt, result {success, stackId?, error?, originalPath, keptOriginalAt?} | null); refusals answer 400/409 with `{error}`.
- GET `/api/stacks/import/migrations` and `/api/setup/migrations` answer `{operations: MigrationOperation[]}` (newest first).
- GET `/api/events` sends `data: {"type": "migration_progress", "operation": MigrationOperation}` for every state change.

Purpose: the user sees progress for long migrations, cannot start the same one twice, and still gets the outcome after a reload.
Output: a hook, a progress/toast helper, updated parent and row components, API clients, tests and Playwright updates. WR-09 stays: the dialog closes on confirm and the parent owns the request and toasts.
</objective>
