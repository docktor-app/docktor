**GitHub issues:** [#72 Migration dialog: real diff, explicit backup, stop old stack](https://github.com/docktor-app/docktor/issues/72). Gap closure round 2 for **18-VERIFICATION.md gap 2** ("Bind-mount data copied into the new stack, and the opt-in pre-migration-backup/ copy, are faithful") = **18-REVIEW.md CR-01** (2026-10-16).

<objective>
Make every directory copy the migration performs faithful: ownership, modes, timestamps and symlinks survive.

Purpose: today `copyDirectory` is a plain recursive `fs.cp`. It never chowns (the copy is root-owned, so Postgres/MySQL/Grafana data directories refuse to start after migration), drops timestamps, and rewrites a relative symlink into an absolute path that points back into the old directory. The same call produces the opt-in `pre-migration-backup/` copy (D-08, MIG-03), which is therefore not a faithful backup. The named-volume path already uses `cp -a`; this plan makes the bind-mount and backup path agree with it.
Output: `VolumeMigrator.copyDirectory` on archive-mode `cp`, a documented port contract, real-filesystem unit tests.

Out of scope: WR-02 (setup-route authentication) is a deferred human decision; WR-03..WR-11 and IN-xx stay open in 18-REVIEW-DISPOSITION.md.
</objective>
