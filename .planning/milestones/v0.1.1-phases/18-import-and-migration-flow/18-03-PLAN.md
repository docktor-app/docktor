**GitHub issues:** [#72 Migration dialog: real diff, explicit backup, stop old stack](https://github.com/docktor-app/docktor/issues/72) (MIG-03 and MIG-04 server side here; the dialog steps are plan 18-05). [#13](https://github.com/docktor-app/docktor/issues/13) is only touched by the docs update in Task 3 (behaviour shipped by plan 18-01).

<objective>
Make `MigrationService.migrate` do exactly what the user chose. Per D-12 both migrate endpoints gain required `backup` and `stopOldStack` booleans (shared schema; the routes from plan 18-02 already spread the validated body). Per D-07/D-08 an opted-in backup is a copy of the old stack directory at `pre-migration-backup/` inside the new stack directory, kept after success; opting out creates none. Per D-10 an opted-in stop runs `docker compose stop` on the old compose file before any data is copied, through a new `ExternalStackControlPort` (the application layer stops shelling out). Per D-09/D-11 rollback never touches the original directory: it removes the new directory and record and restarts the old stack with `docker compose start` (RESEARCH Pitfall 2: never the recreate-capable deploy command) only if Docktor stopped it.

Orchestrator decisions on the research open questions (flagged for the user):
1. `docker.up(stackId)` (Step 8) stays unchanged in both cases; `stopOldStack` governs only the old stack. With stop declined, a port clash makes `up` fail, the rollback runs and the surfaced compose error explains it, consistent with the dialog warning that ports can conflict.
2. A failed `stop` aborts the migration fail-closed; nothing is created.
3. Absolute bind-mount sources read through `/host` (RESEARCH Pitfall 5) are out of scope; see "Deferred items" below.

Purpose: the backup becomes a visible, optional deliverable, the old stack's fate is the user's choice, and a failed migration can no longer destroy the original stack.
Output: port + adapter, reworked `migrate()`, schema flags, route/service/adapter/schema tests, CI contract tests, updated design doc.
</objective>
