**GitHub issues:** [#72 Migration dialog: real diff, explicit backup, stop old stack](https://github.com/docktor-app/docktor/issues/72). Gap closure for UAT gap **G-18-job** (progress): "Progress steps (stopping, copying <volume>, rewriting, deploying, done/failed with rollback message) streamed via the existing SSE/StateBroadcaster channel". Builds on the operation service of plan 18-14; the client plan 18-17 consumes the event.

<objective>
Stream migration progress to the browser over the existing live-state channel.

Purpose: during a long migration the user sees what is happening (and that it is still happening), and a reconnecting client can resync.
Output: step reporting in `MigrationService.execute`, step recording and event emission in `MigrationOperationService`, a new domain event and its StateBroadcaster mapping, tests.

Wire contract (plan 18-17 mirrors it byte for byte): one SSE `data:` frame per change, JSON `{"type": "migration_progress", "operation": MigrationOperation}` where MigrationOperation is the shared `migrationOperationSchema` shape from plan 18-14 (id, stackId, displayName, composePath, backup, stopOldStack, status, step, stepDetail, startedAt, finishedAt, result).
</objective>
