**Implements:** [docktor-app/docktor#45](https://github.com/docktor-app/docktor/issues/45) — mandatory-capable TOTP 2FA (server side): the instance-wide requirement, the forced-enrollment gate, the account security API, and session revocation on 2FA changes.

<objective>
Make "2FA can be made mandatory" real on the server, and make every 2FA change sign out the user's other devices.

Purpose: D-01 requires that a user without 2FA cannot use Docktor while the requirement is on; the only reliable place for that is the shared requireAuth preHandler, so no route file changes. D-02/D-03 define who may flip the requirement and where it is stored. D-10 requires other sessions to be revoked on enable/disable/regenerate, which better-auth does not do by itself (RESEARCH Pitfall 7). The client plans (15-05, 15-06) consume the account API defined here.

Output: a pure domain policy, typed 401/403 errors with a machine-readable code, a split requireSession/requireAuth, an account security repository + application service + routes, better-auth hooks for the guards and revocation, and unit plus integration tests.
</objective>
