Implements GitHub issue docktor-app/docktor #105 (toast never stuck, shared event types, guarded parse, no duplicate resync) and the user-facing contract part of #100 (verified-outcome wording). The PR closes them with `Closes #105` (and `Closes #100` once plans 22-07/22-08 land).

<objective>
Make the migration progress toast always end in done, failed or rolled back, whatever the user does (reload, reconnect, leave the page), and define the shared contracts later plans fill in: the SSE event schemas and the operation statuses, step order and rollback report.

Purpose: ROADMAP SC#5 first clause and MIG-11; D-06/D-07 wording; D-01 step order (rated costly in CONTEXT.md: the order is encoded in the step enum the client's stale-snapshot rule depends on). The shared event schemas must land before Phases 24-25 key permissions on event types.
Output: client operation store + layout toast tracker, shared state-event schemas used by server and client, extended operation contract, honest toast copy.
</objective>
