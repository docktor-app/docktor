Implements GitHub issues docktor-app/docktor #102 (verify the old stack is really stopped), #104 (`~` bind sources) and the "restart only what was running" part of #100. PR closes with `Closes #102`, `Closes #104`.

<objective>
Resolve the old stack's real compose project once, address it explicitly in every stop and start, verify the stop before any data is touched, and handle `~` bind sources from what the old containers really mount.

Purpose: ROADMAP SC#1 and the `~` clause of SC#2; D-04 (hard refusal, no override). This is the shared compose-project resolver the roadmap calls for: plans 22-05 (volume names, anonymous volumes) and 22-07 (rollback restart verification) build on it.
Output: domain/compose-project.ts, ComposeProjectResolverPort + ComposeProjectResolver, project-addressed ExternalStackControl, verified stop and `~` handling in MigrationService, RewriteOptions.homeSources.
</objective>

<assumption_delta_decision>
Detector: `assumption-delta scan 22` fired. Signal "another directory name" (pluralization) is a true positive; signal "backup chosen" (chosen) is a false positive: it is a user option, not a modeling change, so it gets no-change.
Primary noun: the old stack's compose project as Docker runs it, resolved from its containers' labels (com.docker.compose.project plus working_dir/config_files matched by directory identity).
Decision: promote. The resolved project becomes the identity every stop, start, verification and (in later plans) volume naming and rollback addresses with `-p <name>`. The name derived from the files and the directory (domain/compose-project-name.ts) is demoted to the fallback used only when no container of this compose file exists (source "files").
Invariant test (accepted into this plan): external-stack-control.test.ts asserts that every compose argv for the old stack carries `-p <resolved project>`, and migration-service.test.ts asserts that a stack started with `-p other` from a directory named `app` is stopped and verified as `other`.
</assumption_delta_decision>
