<objective>
Close the client-visible half of UAT gap G-08-2 (major, test V2): the "Configuration file changed externally" toast fires for every `config_changed` SSE event, including the one the app itself publishes right after an in-app compose or env save. The server-side half of this gap — actually attaching a `source: "app" | "external"` discriminator to the broadcast — is a separate, independent fix in the companion plan `08-02-PLAN.md`; this plan's `ConfigChangedEvent` mirror and its gating logic are written against that same field name and shape but require no import from server code (per this codebase's existing "hand-maintained mirror" convention for the client's `StateEvent` union).

Purpose: a user who just saved valid compose or env content through the app should see their own tab (and every other open tab) quietly pick up the fresh state — never a toast implying someone or something changed the file behind their back.

Output: `use-stack.ts`'s `config_changed` handler shows the external-change toast only when `event.source === "external"`; an app-initiated event refreshes state with no toast, matching how `config_error` and `update_available` already refresh silently today.
</objective>
