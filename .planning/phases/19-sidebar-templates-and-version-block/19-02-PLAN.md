**GitHub issues:** [#94 Templates as a standalone sidebar destination](https://github.com/docktor-app/docktor/issues/94) (bundle [#96](https://github.com/docktor-app/docktor/issues/96)). The sidebar Templates entry itself was added in plan 19-01; this plan gives it a page.

<objective>
Make Templates a first-class destination. Per CONTEXT D-01 the approved UI-SPEC is the contract: a new route `/templates` mounts the same `TemplateBrowsePage` as `/stacks/create/templates` (UI-SPEC D-04, no redirect), the page derives title, breadcrumb and description from the path, "Use Template" keeps today's behaviour on both routes (UI-SPEC D-05), and Create Stack's "Start from Template" keeps pointing at `/stacks/create/templates` (CONTEXT D-05). Per Claude's Discretion in CONTEXT the header moves into `templates-page-header.tsx`, and the catalog body (loading, repo alerts, new zero-templates empty state, grid) moves into `templates-catalog.tsx` so the page drops from 97 lines to at most 80 (CLAUDE.md page budget).

Purpose: users can browse templates without first entering the create flow, and an empty catalog tells them where to add a repository.
Output: one new route, two new section components, a slimmer page, a router unit test, extended page tests and Playwright coverage of the sidebar journey, the empty state and the 360px layout.
</objective>
