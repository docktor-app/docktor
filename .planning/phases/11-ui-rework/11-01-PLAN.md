<objective>
Tracer slice for Phase 11: prove the reworked stack-detail-page architecture end to end on ONE path before any expansion plan starts. A user opens `/stacks/:id/config`, sees the merged Config tab (Compose File section, Separator, Environment Variables section — no Cards), edits the compose file, saves it through the existing API, and the stack refetches. Old `/compose` and `/environment` URLs redirect to `/config`.

The slice touches every client layer the phase reworks: tab routing (`lib/stack-tabs.ts`), a state hook that owns file loading/dirty-guarding/saving (`hooks/use-stack-config-files.ts`), the new generic flat-section primitive (`components/common/layout/section.tsx`), a page section component (`config-tab.tsx`), the page composition (`[id].tsx`), and a real Playwright E2E. The server layer is deliberately NOT in the tracer: the phase's only server change (plan 11-05, D-09 list enrichment) adds an optional field behind an existing endpoint and has no client-architecture dependency to prove.

Task 2 then expands the proven slice into the full page decomposition so `[id].tsx` becomes a ≤ 90-line orchestrator (CLAUDE.md Known Refactoring Target), and parameterizes the Playwright dev-server port so later waves can run E2E in parallel worktrees.

Purpose: every later plan (overview timeline, dialogs, editors, unsaved-changes guard) builds on these section/hook/page contracts; getting them wrong here would be discovered after ten commits instead of one.
Output: merged Config tab, decomposed stack detail page, Section primitive, port-parameterized Playwright config.
</objective>
