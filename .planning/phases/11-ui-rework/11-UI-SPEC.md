# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase is a **structural and visual rework of an existing, live design system** — not a
greenfield contract. Every value below either (a) documents what `client/src/index.css` and
`components/ui/` already establish, or (b) is a new decision needed for the specific
components/surfaces D-01..D-22 introduce (unified timeline, status pills, dialogs, dark-mode
toggle, StatCard, compose/env editors). Nothing here asks the executor to re-theme existing,
untouched shadcn primitives.

## Spacing Scale

Declared values (must be multiples of 4) — matches Tailwind's default spacing scale already in use throughout `client/src`, no new scale introduced:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge internal padding (`px-2 py-0.5` already used by `Badge`) |
| sm | 8px | Compact element spacing — `gap-2`, table cell padding, timeline entry internal gap |
| md | 16px | Default element spacing — form field gaps, dialog body padding (`px-6` pattern from `Card`/`PageContent`) |
| lg | 24px | Section padding — `PageContent`'s existing `p-6 space-y-6`, Config tab's two stacked sections (Compose / Env) |
| xl | 32px | Layout gaps — space between the unified timeline and any adjacent Overview content |
| 2xl | 48px | Major section breaks — rarely used; reserve for empty-state vertical centering padding |
| 3xl | 64px | Page-level spacing — not expected to be needed this phase |

**Exceptions:**
- **44×44px minimum touch target** for icon-only interactive controls exposed on touch/mobile viewports (dark-mode toggle in `PageHeader`, timeline type-filter icon, per-row remove/edit icon buttons in the env table and proxy/backup dialogs). shadcn's default icon button sizes (`size="icon"` = 36px, `size="icon-lg"` = 40px) fall short — override with an explicit `min-h-11 min-w-11` (44px) wrapper or padding on any icon-only control rendered inside a `<768px` layout, rather than introducing a new button-size token. This directly serves the D-17 mobile audit.
- No other exceptions. All existing spacing in touched files should converge on this 4px-multiple scale during the D-03 Card-reduction pass.

## Typography

Two weights only, matching what shadcn's own primitives already do for **titles** (`CardTitle`,
`DialogTitle`, `SheetTitle`, `AlertDialogTitle` all use `font-semibold`) and what the majority of
existing body/interactive text uses (`font-medium` on buttons/badges/labels, unspecified/regular
elsewhere). New phase-11 components must use exactly **Regular (400)** and **Semibold (600)** —
no `font-bold` (700) in new code.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px (`text-xs`) | 400 Regular | 1.4 |
| Body | 14px (`text-sm`) | 400 Regular | 1.5 |
| Heading | 18px (`text-lg`) | 600 Semibold | 1.2 |
| Display | 24px (`text-2xl`) | 600 Semibold | 1.2 |

**Usage mapping:**
- Label (12/400): timeline timestamps, table column headers, muted captions, helper text under form fields
- Body (14/400): default paragraph/table-cell text, dialog descriptions, env-table values
- Heading (18/600): `CardTitle`/`DialogTitle`/section headers within the Config tab's two stacked sections (already shadcn's built-in default — no override needed when using those primitives)
- Display (24/600): page titles (`PageTitle`), StatCard numeric values

**Exceptions (pre-existing, out of scope to change):**
- `components/ui/*.tsx` primitives (`Badge`, `Button`, `Label`) keep their built-in `font-medium` (500) — shadcn-managed, not edited per CLAUDE.md.
- **Recommended in-scope tightening:** `dashboard.tsx`'s stat-card values currently use `font-bold` (700, e.g. `text-2xl font-bold`) — when extracting `StatCard` (D-14), change to `font-semibold` (600) so the Display role stays inside this contract's 2-weight system. Same applies to `PageTitle` (`components/common/layout/page.tsx`) if touched — converge `font-bold` → `font-semibold`.

## Color

The existing `index.css` token system (light + dark, already complete — see `.dark {}` block) is
the single source of truth. No new tokens are introduced; this section documents the existing
60/30/10 split and adds the semantic status-color contract this phase extends.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`oklch(1 0 0)` light / `oklch(0.145 0 0)` dark) | Page background, dialog/sheet overlay backdrop base |
| Secondary (30%) | `--card`, `--secondary`, `--muted`, `--sidebar` | Cards (used sparingly per D-03), sidebar nav, muted panels, table zebra/hover backgrounds |
| Accent (10%) | `--primary` (`oklch(0.205 0 0)` light / `oklch(0.922 0 0)` dark) | Reserved for: primary CTA buttons (Deploy, Create Stack, Save/Assign in new dialogs), active sidebar nav item, focus rings (`--ring`), links, the dark-mode toggle's active-state icon color |
| Destructive | `--destructive` (`oklch(0.577 0.245 27.325)` light / `oklch(0.704 0.191 22.216)` dark) | Destructive actions only: remove-domain confirmation, discard-unsaved-changes confirmation, delete-stack action |

**Accent reserved for:** primary CTA buttons, active nav item, focus-visible rings, inline links,
dark-mode toggle icon's active/hover tint. Never used for informational badges, table rows, or
decorative emphasis.

**Semantic status-color layer (existing, extend — do not reinvent):** `stack-status-badge.tsx`
already defines a status→color map layered on top of (not replacing) the 60/30/10 surface
palette above:
- Green (`bg-green-500/15 text-green-700 border-green-500/25`) — `RUNNING`/`HEALTHY`; the D-08
  pulsing dot for "running" uses this same green
- Blue, pulsing (`bg-blue-500/15 text-blue-700 border-blue-500/25 animate-pulse`) — transitional
  states: `DEPLOYING`, `UPDATING`, `BACKING_UP`
- Red (`bg-red-500/15 text-red-700 border-red-500/25`) — `ERROR`/`UNHEALTHY` (visually distinct
  from, but conceptually paired with, the `--destructive` token used for destructive actions)
- Yellow (`bg-yellow-100 text-yellow-800 dark:bg-yellow-900 dark:text-yellow-200`) — "config
  changed" pill (`stack-list.tsx`) — the D-09 stack-level "update available" badge must mirror
  this exact placement/class shape, per D-09's explicit instruction, using a distinct hue (e.g.
  blue or a new dedicated hue — not yellow, to stay visually distinct from config-changed)
- Gray (`bg-gray-500/15 text-gray-700 border-gray-500/25`) — `STOPPED`/`DRAFT`

D-11's service-color hash (10 fixed `text-*-400` hues, `log-viewer.tsx`) is a **separate**
per-service attribution palette, not part of the status-color layer — do not conflate the two
when extracting `getServiceColor()` to `lib/service-color.ts`.

## Discretion Decisions (this phase)

CONTEXT.md left five items to Claude's discretion; resolved here so plan-phase and execute-phase
have a single answer to build against:

1. **Status-indicator sizing scheme (D-08):** two sizes, not one — a compact **8px dot** (`w-2
   h-2 rounded-full`) for inline use anywhere space is tight (stack-list rows, timeline entries,
   service rows), and the existing full `Badge` pill for header/summary-level status (stack
   detail page header, Overview tab). Only the `RUNNING` dot pulses: a solid 8px core plus a
   `animate-ping` ripple layer at ~12px, matching the existing `animate-pulse` treatment already
   used on the blue transitional badges but applied at dot scale. All other states render a
   static (non-pulsing) dot of the same 8px size in their status color from the semantic layer
   above.
2. **Dashboard stats (D-14):** six cards total — the existing four (Total, Running, Stopped,
   Errors) plus **"Updates Available"** (count of stacks with at least one service where
   `updateAvailable` is true) and **"Backups Configured"** (count of stacks with an active
   backup schedule). Both new stats reuse the same `StatCard` shape/loading-skeleton as the
   existing four — no new visual treatment.
3. **StatCard home:** `components/common/stat-card.tsx` — a pure `{label, value, icon,
   valueClassName?}` presentational component per CLAUDE.md's own common-vs-domain checklist
   (generic, no domain types in its props); `dashboard.tsx` computes all six counts itself and
   passes them in, exactly like it already does for the first four.
4. **Config tab layout (D-02):** a single stacked column, not sub-tabs — "Compose File" section
   (CodeMirror) then a labeled `Separator` then "Environment Variables" section (table/raw
   toggle) below it. Nested tabs-within-a-tab were rejected as unnecessary UI-navigation debt
   for exactly two sections; a simple stacked layout is consistent with D-03's flattening
   philosophy.
5. **Mobile audit scope boundary (D-17):** the audit itself is timeboxed as one planning task;
   findings are triaged into "fix now" (breaks a core flow at mobile width: deploy, view
   logs/timeline, view/edit config, view status) vs. "file as a follow-up GitHub issue"
   (cosmetic misalignment only), per CLAUDE.md's issue-tracking process — mirroring how Phase 9's
   UAT findings were triaged.
