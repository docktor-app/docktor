## Planning notes

- Spec-less probe fallback skipped (no REQUIREMENTS.md-backed IDs for this phase); truths derive from D-08..D-11 and 11-UI-SPEC.md.
- Tone palette decision: ToneBadge standardises on the pill color scheme already used in six places (`bg-{hue}-100 text-{hue}-800 dark:bg-{hue}-900 dark:text-{hue}-200`), because it is the only existing scheme with dark variants. StackStatusBadge's current `bg-{hue}-500/15 text-{hue}-700` classes have no dark variant and are migrated onto it; the status→hue mapping from UI-SPEC §Color is kept exactly.
- Pulse scope decision (D-08 interpretation): the pulsing dot applies to the whole running family — stack RUNNING and HEALTHY, service container `running` unless `unhealthy`. UI-SPEC Discretion Decision 1 names RUNNING; HEALTHY is a running stack with passing health checks, and a static dot there would read as "less alive" than RUNNING. Transitional states keep their existing badge-level `animate-pulse`.
