**Implements:** [docktor-app/docktor#27](https://github.com/docktor-app/docktor/issues/27) — the server half of the per-stack / per-volume disk usage view (D-13, D-14 amended, D-15 data), plus the BigInt serialization fix (RESEARCH Finding 5) that must land before the first size is written.

No SPEC.md exists for this phase, so no probe-derived predicates were generated; requirements come from GitHub issues with decisions locked in CONTEXT.md.

<objective>
Give the client a single authenticated endpoint that answers "how much disk does each stack use, per volume, plus its local backups, and in total", fed by a daily `du` job that never blocks startup.

Purpose: #27 asks for disk visibility beyond the host-level low-disk warning. D-13 locks the measurement (`du` on `<stack>/volumes/*`, daily, writing the existing `Stack.volumeSizeBytes`/`volumeSizeAt` plus new per-volume rows). D-14 (amended) adds the stack-local `<stack>/backups` restic repository to the picture. RESEARCH Finding 5 shows that the first non-null `volumeSizeBytes` (a Prisma `BigInt`) would make `GET /api/stacks` throw during JSON serialization, so the DTO fix ships in the same tracer that introduces the writer.

Output: one Prisma model + one Stack column + migration, a pure totals rule, a scanner port + adapter, one repository, one application service, one job, one route file. 14-05 renders the Storage page from this endpoint, and 14-07 shows the per-stack figure on the stack Overview.
</objective>
