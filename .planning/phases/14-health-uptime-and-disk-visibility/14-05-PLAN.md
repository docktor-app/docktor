**Implements:** [docktor-app/docktor#27](https://github.com/docktor-app/docktor/issues/27) — the client half of the disk usage view: a sortable per-stack / per-volume table with a total, plus the local backups section (D-15, D-14 amended), on top of 14-02's `GET /api/storage`.

No SPEC.md exists for this phase, so no probe-derived predicates were generated. The UI-SPEC `## UI Considerations` rows for the Storage page are lifted into must_haves.

<objective>
Give the user one page that answers "where is my disk going?": total disk used by Docktor-managed data, a sortable list of stacks by size with each stack's volumes one click away, and the local backup repositories as their own section.

Purpose: #27 asks for disk usage per stack and per volume, sortable, with a total, beyond the host-level low-disk warning. D-15 makes it a new top-level Storage page. D-14 (amended) adds per-stack local backups and defines the grand total as volumes + backups so nothing is counted twice. UI-SPEC section B fixes every layout, sort and copy detail.

Output: an API client, two pure libs, one hook, a ≤80-line page orchestrator with four section components, the route and nav item, a default Playwright stub, and one e2e spec.
</objective>
