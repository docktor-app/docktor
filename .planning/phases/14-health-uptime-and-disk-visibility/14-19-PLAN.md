**Implements:** [docktor-app/docktor#23](https://github.com/docktor-app/docktor/issues/23). Gap closure for 14-UAT.md gap G-14-1a (test 1, major). Root cause: `.planning/debug/probe-attach-blocks-restart.md`.

<objective>
Make Docktor leave no probe network attachment behind when it is stopped normally, so a later start never fails with `network <name> not found`. Add SIGTERM/SIGINT handling that stops the probe job, lets in-flight probes detach, sweeps the alias-marked attachments, closes the app and exits, all with bounded deadlines. Document the recovery for the cases no handler can cover.

Purpose: Docker stores the runtime `network connect` of Docktor's own container (amended D-05) and re-attaches every stored network on each start. If one is gone, Docker refuses to start the container before any Docktor code, including the startup sweep, runs; the restart policy cannot help. Today nothing detaches on shutdown: there is no signal handler and Node is PID 1, so every `docker stop` ends in SIGKILL after the grace period.

Rejected alternative (user decision, not adopted): the helper-container design (14-RESEARCH.md option C), probing from a short-lived container so Docktor's own container is never attached. It would remove the persisted attachment entirely, but it starts a container for every probe of every service every 30 s, which was already the reason it was rejected in 14-RESEARCH.md. It is mentioned in the docs as an evaluated alternative only.

Output: `lib/graceful-shutdown.ts`, an idempotent `HealthProbeJob.stop()`, the wiring in `index.ts`, tests for all three, and one Troubleshooting row.
</objective>
