**Implements:** [docktor-app/docktor#23](https://github.com/docktor-app/docktor/issues/23) — the "visible per stack and per service" half of the health history (D-12 amended), on top of 14-01's `GET /api/stacks/:id/health-events`.

No SPEC.md exists for this phase, so no probe-derived predicates were generated. The UI-SPEC `## UI Considerations` rows for the service health timeline are lifted into must_haves.

<objective>
Let a user open any service on a stack's Overview tab and read its retained health transitions: when it went healthy/unhealthy/starting, from which source, and why.

Purpose: 14-01 persists every transition and serves it over an authenticated endpoint. This plan makes it visible exactly where UI-SPEC section D puts it: an expandable panel per service row, fed by one request per stack. It also adds the `starting` presentation and the `HTTP probe` badge that 14-06's probe source relies on.

Output: an API client, pure formatters, one hook, one section component, edits to ServicesSection/OverviewTab/ServiceStatusBadge, a default Playwright stub, and one e2e spec.
</objective>
