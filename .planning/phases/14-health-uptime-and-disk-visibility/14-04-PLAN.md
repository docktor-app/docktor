**Implements:** [docktor-app/docktor#24](https://github.com/docktor-app/docktor/issues/24) — the server half of the per-stack uptime view, read side: the uptime percentage over a configurable retention window (D-09, D-10) and the incident-list read path over the existing `StackIncident` model (D-11). 14-12 completes the server half with the incident writer and retention pruning.

No SPEC.md exists for this phase, so no probe-derived predicates were generated; requirements come from the GitHub issue with decisions locked in CONTEXT.md.

<objective>
Answer, for every stack, "what share of the observed time in the retention window was it actually up, and which incidents fall in that window?" This plan delivers two authenticated read endpoints and the retention setting that defines the window.

Purpose: #24 needs uptime and incidents over a window.
- D-09 fixes what counts as down: UNHEALTHY/ERROR only, maintenance excluded.
- D-10 fixes the window: global, 30-day default, 1-365.
- D-11 fixes the incident store: the scaffolded `StackIncident` table, one row per episode.
RESEARCH Finding 6 supplies the correctness detail for this plan: uptime comes from `StatusLog` intervals, never from incident durations.

Re-slice note (2026-10-07 revision): this plan's former Tasks 2 and 3 now live in 14-12. They are the incident tracker + subscriber and the daily HealthHistoryPruner. They were moved because the combined estimate (125k, 31 files) exceeded the 100k smart-zone budget. This plan is the tracer slice of #24's server side; 14-12 is its expansion.

Planner decision (CONTEXT discretion on prune mechanics, RESEARCH A9): `StatusLog` is NOT pruned. D-11 keeps it as-is because it also feeds the activity timeline, and pruning it would irreversibly shorten that existing history on upgrade. Instead it gets a `(stackId, createdAt)` index here, so uptime reads stay indexed as it grows. 14-12's pruner deletes only the two Phase 14 history tables.

Output: one index migration, one pure domain module, two repositories (read side), one read service, settings additions, and two routes on 14-01's health route file plus the settings route pair. 14-07 renders the Overview card and incident list from these endpoints. 14-10 renders the stack-list column and the retention card.
</objective>
