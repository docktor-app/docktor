**Implements:** [docktor-app/docktor#23](https://github.com/docktor-app/docktor/issues/23) — the probe engine behind success criterion 1 ("a service can optionally be configured with an HTTP health-probe URL, feeding into the same status model as Docker-healthcheck-derived status"), reading the compose block 14-08's form writes and producing the `http-probe` history entries 14-03 renders.

No SPEC.md exists for this phase, so no probe-derived predicates were generated; requirements come from the GitHub issue with decisions locked in CONTEXT.md (including the 2026-10-07 Post-Research Amendments).

<objective>
Turn an `x-docktor.health-probe` block into a live health signal: every 30 seconds Docktor requests the URL against the service's own container, applies the 3-failures / 60-second-grace rule, and — only when the outcome changes the service's health — writes it, records it as `http-probe` history and pushes the re-derived stack status through the exact event every existing consumer already handles.

Purpose: D-01..D-08 lock config location, success rule, per-service scope, execution and cadence. RESEARCH Pattern 1 fixes the shape (pure producer job → domain rule → application service → existing events), Pattern 2 the scheduler (one 5s tick, per-service due times, own in-flight guard), Pattern 3 the request (node:http + lookup so the Host header survives, no redirect following). Re-emitting `stack.container_state_changed` instead of inventing a new notification path is what keeps ERROR/UNHEALTHY notifications unchanged (#23 criterion 4).

Scope split: this plan delivers the probe → health pipeline. 14-09 makes it coexist with Docker in production — StatePoller/catch-up honoring probe ownership (D-07) and the ephemeral network attach that makes container IPs reachable from Docktor's own network (amended D-05). Both land behind interfaces this plan creates, with no architectural change.

Output: one pure domain module, two domain events, one compose reader, one port + adapter, one application service + subscriber, one job, wiring, and unit, preservation and integration tests.
</objective>
