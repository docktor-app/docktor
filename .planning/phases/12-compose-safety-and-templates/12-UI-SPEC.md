## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside badges/buttons |

| xl | 32px | Layout gaps between major page sections |
| 2xl | 48px | Major section breaks (not expected to be needed within this phase's compact dialogs/cards) |
| 3xl | 64px | Page-level spacing (not expected to be needed within this phase) |

Exceptions: `p-3` (12px) is inherited from shadcn's own `Card`/`Alert` default internal padding (already used project-wide, e.g. `create.tsx`'s error banner) — accepted as a shadcn-primitive default, not a new value authored for this phase. No icon-only 44px touch-target exception is needed — this phase introduces no icon-only interactive controls (all new buttons carry visible text labels).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Diff+warning dialog title | `Review changes to {stackName}` (compose) / `Review changes to {stackName}'s environment` (.env) |
| Diff+warning dialog primary CTA | `Confirm & Apply` |
| Diff+warning dialog secondary action | `Keep Editing` (returns to the editor without saving — not a generic "Cancel", since the user's edit is still live in the editor) |
| Diff dialog — no-op guard | If `before === after` (byte-identical), skip the dialog entirely and save directly — this is the general form of D-02's "skip on first save" rule; the dialog only ever appears when there is a real diff to confirm |
| Always-on finding badge copy (red) | `{ruleLabel}` e.g. `Privileged container`, `Docker socket mounted`, `Bind mount outside stack directory` — short, scannable, no punctuation |
| Configurable finding badge copy (yellow) | `{ruleLabel}` e.g. `Named volume`, `Inline environment variable`, `.env not referenced` |
| Finding tooltip body | One sentence: what it means + why it's flagged, mirroring `compatibility-badge.tsx`'s tooltip style (e.g. "This service has `privileged: true`, granting it full access to the host. Confirm this is intentional before applying.") |
| Primary CTA — Create Stack page template entry point | `Start from Template` (secondary button next to the existing blank-compose flow, not a replacement for it — create.tsx's existing "Create Stack" form stays the blank-slate path) |
| Primary CTA — template grid card | `Use Template` |
| Primary CTA — variant-selection dialog | `Use this variant` (when a template has multiple variants); when a template has exactly one variant, skip the dialog entirely and treat the card's `Use Template` click as selecting that sole variant directly (see UI Considerations — zero-one-many) |
| Template grid search/filter empty state heading | `No templates found` |
| Template grid search/filter empty state body | `Try a different search term or category — or start from a blank compose file instead.` (links back to the existing blank-slate Create Stack form) |
| Template grid — first-run / index not yet synced | `Templates are loading for the first time — this can take a moment.` (with a `Skeleton` grid underneath, not a bare text-only state) |
| Template repo sync error | `Couldn't load templates from {repoUrl} — check the repository URL and try again.` + a `Retry` button |
| Compose Checks settings card title | `Compose Checks` |
| Compose Checks card primary CTA | `Save Compose Checks` |
| Compose Checks card per-check switch labels | `Flag named volumes`, `Flag inline environment variables`, `Flag .env files with no env_file reference` — verb-first, matching the rule's action, not its internal rule-id |
| D-04 skip-diff toggle label (lives in Compose Checks card) | `Skip the review step before applying compose/.env changes` with helper text `Changes are applied immediately without a diff preview. You can turn this back on at any time.` |
| Port-conflict warning — Docktor-managed stack case | `Port {port} is already in use by {stackDisplayName}.` where `{stackDisplayName}` renders as a link to that stack's detail page (D-15) |
| Port-conflict warning — non-Docktor process case | `Port {port} is already in use by {processName} (PID {pid}).` — plain text, no link (D-15) |
| Port-conflict warning — unknown process case | `Port {port} is already in use by another process.` (the documented fallback per D-13/research when `ss`/`lsof` can't identify the holder) |
| Port-conflict surfacing mechanism | A persistent `Alert` banner on the stack detail page, styled identically to `stack-alerts.tsx`'s existing yellow `configChanged` banner (same `bg-yellow-100 ... dark:bg-yellow-900 ...` classes) — **not** an ephemeral `sonner` toast. Rationale: D-14 fires automatically on every deploy and can report multiple conflicts; a banner survives long enough to be read and act on, where a toast could be missed, and it naturally extends the page's existing alert-banner slot rather than introducing a second notification channel. If more than one port conflicts in a single deploy, render one `Alert` listing all conflicts (one line per port), not N stacked banners. |
| Destructive confirmation | **None introduced by this phase's locked scope.** D-05/D-19 only requires *adding* a template repo, not removing one. If a "remove template repo" action is added during planning, it must follow `restore-confirm-dialog.tsx`'s type-to-confirm `AlertDialog` pattern, with suggested copy: `Remove {repoUrl}: this stops template updates from this source. Stacks already created from it are unaffected.` — flag this as a planning-time addition, not a pre-approved locked requirement. |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 13 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Diff+warning dialog | ✅ covered | Byte-identical before/after skips the dialog entirely (generalized D-02 no-op guard, see Copywriting Contract) — the dialog never renders an "empty diff" state because it never opens for one |
| empty | Template grid (no search/filter match) | ✅ covered | Renders the "No templates found" heading + body from Copywriting Contract, with a link back to the blank-slate Create Stack form |
| empty | Template grid (first-run, index not yet synced) | ✅ covered | Renders the "Templates are loading for the first time" copy over a `Skeleton` grid, not a bare spinner or blank page |
| loading | Template grid (subsequent fetches) | ✅ covered | `Skeleton` card grid, same shape as `ProxySettingsCard`'s loading branch |
| loading | Compose Checks settings card | ✅ covered | `Skeleton` rows mirroring `ProxySettingsCard`'s exact loading-branch structure (label + control skeleton pairs) |
| loading | Diff+warning dialog (computing diff/findings) | 🧪 backstop | Dialog should not show stale/blank content while the server computes the diff — a loading indicator inside the dialog shell before content is ready is expected but not pinned to an exact spinner/skeleton choice; verify at execution time that the dialog never flashes empty before populating |
| error | Template repo sync failure | ✅ covered | Renders the "Couldn't load templates from {repoUrl}" `Alert` + `Retry` button, matching `proxy-settings-card.tsx`'s destructive-`Alert`-with-detail pattern |
| error | Port-conflict check itself fails (e.g. Docker socket unreachable) | ✅ covered | Fails silently from the user's perspective — per D-14/research, the check is best-effort and non-blocking; a check failure must never surface as a blocking error or prevent deploy, it simply means no conflict banner renders that time |
| populated | Diff+warning dialog with both diff and findings | ✅ covered | D-03's locked requirement — unified diff with findings interleaved next to the lines that triggered them, scrollable via `ScrollArea` |
| populated | Template grid with many templates/variants | ✅ covered | Standard responsive card grid (reuse the dashboard's existing card-grid breakpoints from Phase 11), category filter narrows via the native `<select>` |
| partial | Template with some variants documented, others missing metadata | 🧪 backstop | Not explicitly addressed in CONTEXT.md/RESEARCH.md; assume a variant missing required metadata (name/description) is excluded from the picker rather than rendered broken — verify this fallback exists at execution/review time rather than treating it as locked |
| overflow | Diff dialog with a very long diff or many findings | ✅ covered | `ScrollArea`-wrapped content panel (per Component Inventory), dialog itself does not grow unbounded |
| overflow | Port-conflict banner with multiple conflicting ports in one deploy | ✅ covered | Single `Alert` lists all conflicts (one line per port) per Copywriting Contract — never N stacked banners |
| zero-one-many | Template variant count (0 handled as a data-integrity concern, 1, many) | ✅ covered | A template with exactly one variant skips the variant-selection dialog entirely (per Copywriting Contract primary-CTA row); a template with zero variants is a template-repo authoring error, not a UI state this phase needs to render gracefully for — out of scope per D-06's "self-contained folder per variant" structure assumption |
| long-text | Template card name/description, process name in port-conflict message | ✅ covered | Template card description uses `line-clamp-2` + a `title` attribute carrying the full text on hover, matching `StatCard`'s existing `truncate`+`title` convention; port-conflict process-name strings render as plain inline text with no truncation (process names are short by OS convention, unlike arbitrary descriptions) |
