<objective>
Build the two infrastructure adapters the template feature needs, TDD-first and without touching the database: `GitExecutor` (safe shallow clone / fast-forward pull of a template repo into a local cache, serialized and atomic) and `TemplateSourceReader` (walks a checkout, validates every template and variant against shared Zod manifests and safety limits, and returns a deterministic index plus human-readable issues). Task 1 is the tracer: a real local bare repo is cloned and one valid template with one variant is read back. Task 2 adds pull/re-clone/locking, URL rejection, every validation/limit path, and the docs.
Output: two port-backed infrastructure classes, shared template schemas, authoring doc.
</objective>

## Planning notes

- **Format decision (Claude's discretion within D-06):** template-level metadata lives in `templates/<template>/template.yml` (shared by its variants: name, description, category, optional icon file) and each variant folder holds `variant.yml` (name, description, optional usage), `docker-compose.yml`, optional `.env.example`. `template.yml` carries `schemaVersion: 1` so the format can evolve without breaking existing repos.
- Icons are files inside the template folder embedded as data URIs (≤ 64 KiB, svg/png) — never a remote URL, so browsing templates makes no third-party requests.
- `git` is installed in the runtime image by plan 12-03; dev hosts and CI runners already have it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-supplied repo URL → git process | an authenticated user's URL becomes a git argument |
| remote git repository content → local filesystem → parser | untrusted repo files (possibly hostile) are checked out and read |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-13 | Elevation of Privilege | GitExecutor (git URL → argv) | high | mitigate | Shared `isAllowedGitRemoteUrl` allowlist (https/git/ssh only; rejects leading "-", "::" ext:: syntax, file://, credentials) at the schema AND inside syncCheckout; URL passed after `--`; `GIT_ALLOW_PROTOCOL` + `-c protocol.ext.allow=never`; execFile argv only |
| T-12-14 | Information Disclosure | TemplateSourceReader (symlinks) | high | mitigate | Clone/pull with `-c core.symlinks=false`; every file/dir checked with `lstat` and non-regular entries rejected, so a repo symlink can never make Docktor read a host file into the template index |
| T-12-15 | Denial of Service | clone / reader | medium | mitigate | `--depth 1 --single-branch --no-tags`, 60 s git timeout, per-file byte limits, MAX_VARIANTS_PER_REPO cap |
| T-12-16 | Tampering | template/variant directory names | medium | mitigate | Names come from `readdir` (no traversal segments) and must match TEMPLATE_SLUG_PATTERN; cache path is derived from a database id by the caller, never from the URL |
| T-12-17 | Spoofing | interactive git credential prompts | low | mitigate | `GIT_TERMINAL_PROMPT=0`; credentials in URLs are rejected (private repos are out of scope for #19) |
| T-12-SC | Tampering | package installs | low | accept | No package-manager installs in this plan; the `git` binary comes from Debian apt (plan 12-03) |
</threat_model>
