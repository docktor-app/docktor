## Planning notes

- **D-04 × #20 reconciliation (interpretation, flagged):** D-04 says the review dialog can be skipped "at all" via Settings, but #20 AC1 and ROADMAP SC3 require a confirmation dialog before a dangerous configuration is applied. Rule implemented: `confirmationRequired = hasChanges && (!skipReview || <the edit introduces ≥1 finding>)`. A finding is "introduced" when its (ruleId, serviceName, message) key is absent from the evaluation of the pre-edit state, so a stack that already had `privileged: true` is not re-prompted on every unrelated .env edit when skip is on. Plan 12-06 states this in the toggle's helper text.
- Create flow (D-02): no diff; `confirmationRequired = findings.length > 0` (every finding is introduced for a new stack); the skip toggle does not apply because there is no diff step to skip.
