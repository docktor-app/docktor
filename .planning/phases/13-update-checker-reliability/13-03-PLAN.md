**Implements:** [docktor-app/docktor#29](https://github.com/docktor-app/docktor/issues/29) (D-10, D-11).

<objective>
Stop the `ImageUpdateCheck` table growing without bound. Today no deletion path exists, so every retired image+tag keeps its row forever. A dedicated daily sweep job, which also runs once at startup to clear the existing backlog, deletes every row whose imageRef no current service produces.

The "current" set is computed by exactly the rule UpdateChecker uses. The query is moved out of `update-checker.ts` into `ImageUpdateCheckRepository` and shared by both jobs, which makes the pruner safe by construction (D-11). The move also removes `update-checker.ts`'s direct Prisma access, a CLAUDE.md violation.

Tracer (Task 1): shared ref query → delete method → job → registration, proven against a real database. Task 2: edge cases (empty table, read failure, idempotency, prefix normalisation) and relocation of UpdateChecker's second Prisma query.

Output: two repository methods (three after Task 2), the `ImageUpdateCheckPruner` job, registration, and unit and integration tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| registry responses → ImageUpdateCheck rows | written only by UpdateChecker (unchanged); the pruner never reads registry data |
| background job → database | daily deleteMany over a cache table |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-10 | Tampering | malicious/compromised registry response influencing pruning | low | mitigate | The prune set is computed only from Service rows (compose-derived) via findTrackedImageRefs. The pruner imports no registry/Docker client (grep gate). Registry data can only change column values of rows keyed by service-derived refs, never which refs exist. |
| T-13-11 | Denial of Service | pruner wiping live rows (badges vanish, re-check burst against registry rate limits) | medium | mitigate | A read failure rejects before any delete and is never coerced to an empty set (unit-tested). An empty set occurs only with genuinely zero services. Live refs are excluded by construction (integration-tested). UpdateChecker's 6h/N stagger bounds any re-check burst. |
| T-13-12 | Tampering | race with an in-flight UpdateChecker upsert re-creating an orphan | low | accept | Harmless cache row, removed by the next daily run (backstop truth). |
| T-13-13 | Denial of Service | large NOT IN list | low | accept | Bounded by the distinct image+tag count on a single self-hosted Docker host. |
</threat_model>
