**GitHub issues:** [#72 Migration dialog: real diff, explicit backup, stop old stack](https://github.com/docktor-app/docktor/issues/72). Gap closure for UAT gap **G-18-4** part (A), dialog half: relative bind mounts were never offered, copied or rewritten ("Volumes to copy: 0" for the memos stack). The scan half is plan 18-09, the diff fidelity plan 18-08.

<objective>
Offer relative bind mounts in step 1 of the migration dialog, default to moving them into `./volumes/<name>`, let the user keep a mount at its relative path per mount (with a warning), count them, and send them in the preview and migrate requests.

Purpose: a migrated stack starts with its data instead of an empty `./data`, and the review diff shows the real rewrite.
Output: a pure path-rules helper in `client/src/lib/` with tests, the select step and wizard wired to it, wizard tests, and a Playwright scenario.

User decision (G-18-4): default new path `./volumes/<basename>` per the design doc; the user decides per mount (convert or keep); a mount that is not converted into the Docktor-managed layout shows a warning. "Keep" follows the debug session's alternative: the mount keeps its relative path and its data is copied to that path in the new stack directory, so the new stack still finds its data.
</objective>
