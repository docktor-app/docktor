<objective>
Give the server one canonical notion of "the same directory" and use it wherever a migration or import compares directories: the in-place/nested/separate classification and the already-managed detection.

Purpose: today `classifyMigrationTarget` and `findManagingStack` compare path strings. Inside Docktor's container one folder has several spellings: the scan sees `/host/home/.../stacks/memos`, the stacks folder is mounted at its identical host path `/home/.../stacks/memos`, and symlinks add more. A stack already in the stacks folder therefore classifies as "separate" and the exists-check refuses it (G-18-22-inplace); a managed stack scanned through `/host` is offered for import again (WR-10). This plan builds a namespace-tagged identity from `fs.realpath` and Docktor's own bind mounts (no hard-coded `/host`), classifies by it, and runs an in-place migration through the writable stacks-folder spelling because `/host` is read-only.
Output: pure `directory-identity.ts` with tests, `DirectoryIdentityPort` and its resolver, identity-based `classifyMigrationTarget` and `findManagingStack`, and `MigrationService`/`OnboardingService` wired to them.

Out of scope: container-to-stack matching in the StatePoller (plan 18-25 consumes `identifyLabel` from this plan), the project-name collision refusal (18-26), the own-stack file check (already mount-aware via `containerVisiblePaths`), and the in-flight guard keys of the operation service.
</objective>
