**GitHub issues:** [#13 Import existing stack](https://github.com/docktor-app/docktor/issues/13) (scan surface) and [#72 Migration dialog](https://github.com/docktor-app/docktor/issues/72). Gap closure for UAT gaps **G-18-3-scan** (server half: per-directory skip reasons) and **G-18-4** part (A), server half (the scan never reported relative bind mounts). The UI halves are plans 18-13 (skip reasons) and 18-10 (relative mounts in the dialog).

<objective>
Make the scan report why a requested directory produced nothing, and report relative bind mounts, through one shared scan contract.

- G-18-3-scan: `BrownfieldScanner` counts an unreachable root (ENOENT) as skipped with only a server-side warning, so the user sees a silently missing stack. Return each skipped root with a reason.
- G-18-4 (A): the scanner keeps only absolute bind mounts (`brownfield-scanner.ts` lines 144-146), so `./data` is never offered, copied or rewritten. Return relative mounts too.
- The scan DTO is declared twice today (server interface in the scanner, client interface in `brownfield-types.ts`); move it into `@docktor/shared` (CLAUDE.md: shared schemas are the single source of truth; 18-02 precedent for brownfield bodies, `environmentReportSchema` precedent for response shapes).

Purpose: the scan tells users which roots were not found or not readable, and the migration dialog gets the data it needs to copy relative mounts.
Output: shared scan schemas and types, scanner changes with tests, client type re-export, fixtures updated for the new required field.
</objective>
