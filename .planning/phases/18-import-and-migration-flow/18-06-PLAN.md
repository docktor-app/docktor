<objective>
Close the two verification gaps in `MigrationService.migrate()` so the 18-03 rollback guarantee (D-09, D-11) holds for every failure, and so rollback only ever undoes what the current run did.

- CR-01: the Step 5 bind-mount copy today wraps both the existence check and the copy in one bare catch that creates an empty destination. Any copy failure is reported as success with missing data, after the old stack was already stopped (D-10 default on). Only ENOENT on the existence check may mean "empty source"; everything else must reach the rollback.
- CR-02: the target-directory check is check-then-act, the directory is created with mkdir -p, and the record delete in the rollback is unconditional. A concurrent same-slug run can therefore delete another run's directory and record. Fix with an exclusive leaf mkdir and a `recordCreated` flag, and move every side-effect-free refusal into a `preflight()` that throws typed errors before anything is stopped. The remaining two CR-02 items land with the background operation (UAT G-18-job): the per-slug in-flight 409 in plan 18-14 and the disabled in-flight rows on the client in plan 18-17.

Purpose: a failed migration is reported as failed and restarts the old stack, no run can ever delete a directory or record it did not create (D-09 invariant), and refusals are known before any side effect so a background start can answer them synchronously.
Output: shared `hasErrorCode` guard, reworked migrate() (`preflight` + `execute`) with tests, exclusive directory creation on the port and adapter with tests.
</objective>
