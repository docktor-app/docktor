  <action>
Run three scans over the server workspace, record every finding in a table, then act on each according to the disposition rules below. Findings are not predetermined; the table is the deliverable, and it must contain every row the scans produce, including the ones left in place.

**Scan A — unused declarations, parameters and imports.** From the repository root:

`yarn workspace @docktor/server exec tsc --noEmit --noUnusedLocals --noUnusedParameters --composite false --declaration false --declarationMap false -p tsconfig.json`

This is a one-off invocation, not a configuration change — do not add these flags to `server/tsconfig.json`, which would make them a build gate this phase never agreed to. The baseline at the phase's starting commit was nine findings, listed here so a smaller or different list is recognised as progress rather than as a broken scan: an unused decryption import in the notification service; an unused result type in the brownfield scanner; two unused parameters in the compose rewriter; two unused parameters in the restic executor; an unused path import in the volume migrator; an unused repository binding in the update checker; an unused event type import in the stacks route. Several of these files are rewritten by earlier waves, so re-run the scan rather than working from this list.

**Scan B — exports nothing outside their own file references.** From `server/`:

`for f in $(git ls-files 'src/**/*.ts' | grep -v '^src/generated/'); do for n in $(grep -oE '^export (async function|function|class|const|interface|type|enum) [A-Za-z0-9_]+' "$f" | awk '{print $NF}'); do c=$(git grep -l -w "$n" -- 'src' 'test' | grep -v "^$f$" | wc -l); [ "$c" -eq 0 ] && echo "$n $f"; done; done`

**Scan C — declared dependencies nothing imports.** From `server/`:

`node -e "const p=require('./package.json');for(const d of Object.keys(p.dependencies||{}))console.log(d)" | while read d; do c=$(git grep -l -E "from \"$d(/|\")" -- 'src' | wc -l); [ "$c" -eq 0 ] && echo "UNIMPORTED $d"; done`

**Disposition rules — apply these, do not improvise per finding:**
- A runtime value (function, class, constant) with zero references anywhere in `src` or `test` outside its own definition: **delete it**, together with any test whose only subject is that symbol.
- An exported type or interface referenced only inside its own file: **drop the `export` keyword**. The symbol is live within the file; only its published surface is dead. Deleting it would be a different change than the audit proved was safe.
- An unused parameter that an implemented interface requires: **prefix it with an underscore**. Deleting it would silently change a contract, which the audit has no evidence is safe.
- An unused import or local: **delete it**.
- A symbol whose only reference is its own test, where the symbol is production code: **delete both**, and name it in the table — a production symbol whose sole consumer is its test is the same defect Task 1 removes.
- A symbol the scan flags that a **later phase** is known to need: **leave it, record the row, and name the phase and the reason**. Guessing is not a disposition; if there is no named phase and no reason, the symbol is dead.
- Anything under `server/src/generated/`: **out of scope**, never edited — it is Prisma output regenerated from the schema.
- A dependency Scan C reports: **record it and leave it in place unless its absence from the source is confirmed by a second reading**; a package reached only through configuration or a binary rather than an import statement is a false positive of this scan, not dead weight.

Every deletion must be justified by a scan result recorded in the table. A symbol that merely looks unused is not a finding — CLAUDE.md's refactoring rule asks for dead code removed, not for guesses acted on.

After acting, re-run Scan A and leave it clean. Re-run Scans B and C and record the residual rows with their dispositions; those two scans legitimately end non-empty, because "exported but only used locally" and "reached without an import statement" are both states the rules above resolve by recording rather than by deleting.
