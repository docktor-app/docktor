<objective>
Migrate all seven background jobs onto the `Job` contract and the base classes plan 10-04 shipped, and replace `jobs/index.ts`'s seven duplicated try/catch calls with the registry.

Purpose: this is where D-02/D-13/D-14 become real. It also closes a concrete existing defect — `stopJobs()` today calls each job's `stop()` with no isolation, so one throwing stop (for example the file watcher's awaited close) aborts the remaining stops and can leak a running cron task or Docker event stream on shutdown.
Output: seven jobs with their scheduling boilerplate factored into base classes, a `jobs/index.ts` that registers and delegates, and a rewritten registry test suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process startup -> database | Jobs start before the database is guaranteed reachable on a cold compose start; a start failure must not take the HTTP server down |
| process shutdown -> Docker event stream / chokidar watcher | A leaked watcher or event stream outlives the shutdown path |
| route -> `BackupScheduler.upsert` | A client-triggered settings change creates and destroys cron tasks at runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-13 | Denial of Service | `startJobs()` cold-start path | high | mitigate | Registration order is asserted identical to the current start order, and `startAll()`'s sequential per-job isolation (verified in 10-04) preserves the contract that a database-not-ready failure cannot take down the process — the exact regression STATE.md records from Phase 02 |
| T-10-14 | Denial of Service | shutdown leak | high | mitigate | `stopAll()`'s per-job isolation is exercised by a new test case asserting a later job still stops after an earlier `stop()` throws, closing 10-RESEARCH.md Pitfall 4 |
| T-10-22 | Tampering | cron expression drift | medium | mitigate | Every cron literal is recorded before and after and asserted byte-identical; scheduling moves location but never value. A silently widened schedule would change how often Docker, registries and disks are polled |
| T-10-23 | Denial of Service | `BackupScheduler.upsert` from a route | medium | accept | Unchanged by this plan — the existing cron-expression validation and the route's own auth gate remain the controls; this plan does not alter the upsert path |
| T-10-24 | Information Disclosure | health reporting from job bodies | medium | mitigate | Jobs report an error message through the reporter installed in 10-04, which stores the message only (T-10-11); job bodies are not changed to pass config or env objects into the reporter |
| T-10-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed; the cron package is the already-installed one (D-12) |
</threat_model>
